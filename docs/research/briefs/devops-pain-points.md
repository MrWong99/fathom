# devops-pain-points

**Dimension:** DevOps pain evidence: editing values in plain YAML/env without validation, push, wait for pipeline/controller, discover failure, roll back (2024-2026).

## State of the slice in 2026

The pain is real and quantified at the outcome level, almost never at the failure-class level. Strongest outcome numbers: Komodor 2025 Enterprise Kubernetes Report (Sep 17 2025; "hundreds of production environments / thousands of incidents"): 79% of production issues originate from a recent system change; median MTTD ~40 min, MTTR >50 min for high-impact outages; 38% of companies see high-impact outages weekly; >60% of ops time is troubleshooting; only 20% of incidents resolve without escalation; only 7% of workloads have accurate requests/limits, 65% use <50% of what they request; typical enterprise runs >20 clusters, nearly half operate 4+ environments. CNCF 2025 survey (published Jan 20 2026): 82% of container users run K8s in prod; GitOps used "extensively" by 58% of "innovators" but only 23% of "adopters"; complexity cited by 34% but now behind cultural/organizational blockers (47%) — the narrative moved from "YAML is hard" to "operating model is hard" while the config-change failure rate has not moved. DORA 2025 added Rework Rate ("effort spent fixing defects users encountered") beside Change Failure Rate and found AI adoption correlates with worse stability (more change failures, more rework) even as individual throughput rises. Red Hat State of Kubernetes Security 2024 (600 respondents, Jun 2024): 67% delayed/slowed deployments due to security concerns. Fairwinds 2024 benchmark (330k workloads): 67% of orgs have >11% of workloads missing CPU requests, ~65% missing liveness/readiness probes, 70% have >=11% outdated Helm charts.

Failure-class evidence is qualitative. Syntax/type-coercion is acknowledged upstream: KEP-5295 KYAML (alpha 1.34 Aug 2025, then beta, reported GA in 1.37 Sep 2026 — unverified) exists because "wrongly indented YAML ... is syntactically valid but does not marshal properly" and NO/yes/ON coerce to booleans. Skyscanner 2021 (4h+ global outage from "a couple of characters" missing in a templated manifest) remains the canonical templating story; GitLab #388091 shows CI YAML failing silently (trailing spaces around `include:` -> no pipeline, lint shows nothing). Helm's values.schema.json is optional and rare ("the values.yaml has no type schema, just vibes", HN Jul 2025; "helm itself can't say 'you typed 1000M cpu, but probably meant 1000m'"); "string based templating and lack of type safety" recurs on every Helm-alternative thread (Glasskube 266pts, Holos 77pts, KubeForge 62pts). Policy/admission denials in GitOps are post-merge by construction (CNCF blog Apr 2 2026: Enforce-mode violation -> Argo CD sync fails, app OutOfSync/Degraded; dev.to Apr 2026: "Developers will only discover policy violations after merging"). Quota: server dry-run accounts for it, client tooling does not ("exceeded quota: cpu-request, requested: 2000m, available: 1000m"; "admission webhook 'validation.gatekeeper.sh' denied the request"). Missing Secret/ConfigMap refs -> CreateContainerConfigError after scheduling; bad tags -> ImagePullBackOff; RBAC -> "forbidden: User 'system:serviceaccount:argocd:argocd-application-controller' cannot create resource". Env drift: "Each layer can mutate values. The final output only appears inside the GitOps engine after it renders everything" (platformengineering.org Feb 2026); Octopus anti-pattern #20 "You need to manually run Helm in your head".

Feedback-loop timing: Argo CD polls Git every 120s + 60s jitter (max 3 min) without webhooks; ApplicationSet PR generator polls every 1800s by default; Flux minimum interval 60s, docs recommend 60m Kustomization interval in prod (landing = GitRepository interval + Kustomization interval, ~11 min with 1m/10m); CI: "30-60 minutes waiting for CI" per PR (HN Jan 2026), "CI builds taking upward 2h"; LeadDev merge-train case (Sep 2026): 45 merges/340 runs a day, median merge-to-main <20 min after optimisation vs half a day at worst, "every minute of merge-train time represented roughly six engineering hours of blocked time daily"; LeanOps models 3-5 pushes per PR producing 2-4 redundant CI runs. With Komodor's 40 min MTTD, edit-to-"know it was wrong" is 10 minutes to hours; know-to-rolled-back adds ~50 min median. Dominant practice is a stack of partial client-side checks (yamllint + kubeconform + Datree CRDs-catalog + kustomize build + helm lint + conftest; kyverno apply; helm diff / argocd app diff; Argo ServerSideDiff stable since v3.1; rendered-manifest pattern), each explicitly scoped and assuming a live cluster for the parts that bite. Direction: K8s is making truth machine-readable — ValidatingAdmissionPolicy (CEL) GA since 1.30 with paramKind and Deny/Warn/Audit; Declarative Validation GA in 1.36 (May 2026) "publish validation rules via OpenAPI and integrate with ecosystem tools"; manifest-based admission alpha 1.36 loads policies from files on the apiserver; KYAML removes the syntax class. Typed alternatives (CUE/Timoni/Holos; Helm 4 Nov 12 2025 with WASM plugins + server-side apply) meet adoption reluctance. Whitespace: nobody ships an offline "pseudo cluster" bundling schemas + CRDs + VAP/Kyverno/Gatekeeper policies + ResourceQuota/LimitRange + referenced Secrets/ConfigMaps + RBAC + registry tags into one snapshot a values editor can validate against before push.

## Strongest pain-point evidence

- **Change-caused incidents dominate**: 79% from recent change; MTTD ~40 min, MTTR >50 min; 38% weekly high-impact outages; >60% ops time troubleshooting (Komodor 2025, Sep 17 2025, komodor.com + BusinessWire). Note: conflates config with all change types.
- **Policy denials discovered post-merge**: Enforce-mode violation -> Argo sync fails, OutOfSync/Degraded (CNCF blog Apr 2 2026); "only discover policy violations after merging" (dev.to sodiqjimoh Apr 2026).
- **YAML syntax/coercion is systemic**: KEP-5295 rationale; KYAML alpha 1.34 (Aug 27 2025).
- **One templating char = hours of outage**: Skyscanner Aug 2021, missing `{{ }}` -> mass deletion, 4+ h global (k8s.af; Glasskube compilation May 27 2024).
- **Helm values have no schema**: "just vibes" (NewJazz, HN Jul 18 2025); 1000M vs 1000m (jrockway); "string based templating and lack of type safety" (fsniper); templates don't check results (mdaniel) (HN 44608856, 40789862).
- **Multi-layer merging hides the final result**: platformengineering.org Feb 9 2026 (Artem Lajko); Octopus #20.
- **CI wait dominates inner loop**: "30-60 minutes waiting for CI" (philip1209, Jan 2026); "<5 minutes 90% of which was waiting for CI" (IceDane, Dec 2025); "upward 2h ... destroys small commits" (TeMPOraL); LeadDev Sep 7 2026 merge-train figures.
- **Controller latency before failure is even known**: Argo 120s+60s; PR generator requeueAfterSeconds 1800; Flux 60s min / 60m prod (Argo FAQ/auto_sync/PR generator docs; Flux docs).
- **Client validators explicitly don't cover prod breakage**: kubeconform README; kubectl-validate README; kyverno apply reference.
- **Server-side checks need cluster + permissions editors lack**: dry-run docs; argocd app diff docs; helm-diff README.
- **Late runtime errors map to missing pre-push checks**: CreateContainerConfigError "usually a missing Secret or ConfigMap"; quota/gatekeeper/RBAC strings above (Komodor troubleshooting guide; adhdecode).
- **Requests/limits chronically wrong**: 7% accurate, 65% <50% used, 82% over-, 11% under-provisioned (Komodor 2025); 67% orgs >11% missing CPU requests, ~65% missing probes (Fairwinds, CNCF Jan 26 2024); Sysdig 2025 60% no CPU limits / 51% no memory limits (search summary only).
- **Security slows deployment**: 67% delayed; 42% cite security top concern (Red Hat Jun 26 2024).
- **CI YAML fails silently**: GitLab #388091.
- **AI throughput raises instability/rework**: DORA 2025 via Splunk, leecampbell.com Jan 2026.
- **GUI YAML editors must be schema-guided**: KubeForge HN 44752469 (Aug 1 2025): "no guidance whatsoever"; want mandatory-first assist dialog; validation icon gap.
- **Typed config languages resisted**: HN 42366665 Holos (Dec 9 2024); "config languages with logic ... very hard to debug".

## Design implications (all retained)

1. **Pseudo cluster = versioned snapshot bundle from plain kubectl reads**: server OpenAPI v3 for the exact minor; all CRDs incl. `x-kubernetes-validations` CEL; VAP + Bindings + param objects; Kyverno ClusterPolicy/Policy + PolicyException; Gatekeeper ConstraintTemplates/Constraints; ResourceQuota + LimitRange per namespace; Namespace labels; PodSecurity admission labels; existing Secret/ConfigMap names+keys (never values); ServiceAccount/Role/RoleBinding for the deployer identity; optional registry tag lists. Every evidenced failure class maps to one input.
2. **Offline evaluation order, each result labelled with confidence**: (1) YAML/KYAML parse + coercion warnings; (2) schema (OpenAPI/CRD, `-strict` semantics); (3) CRD CEL + VAP CEL via cel-go with snapshot params; (4) Kyverno/Gatekeeper with simulated context (namespace labels, existing resources, GitOps controller SA userInfo); (5) quota/limitrange arithmetic vs snapshot usage; (6) reference checks (secretKeyRef/configMapKeyRef/serviceAccountName/image tag); (7) RBAC "can deployer SA create this kind here". Report Info/Warning/Blocking as zhi severities; Blocking mirrors validationActions Deny / Enforce.
3. **Optional online verify**: `kubectl --dry-run=server` with fieldManager = GitOps controller's manager when reachable; offline result must explain the delta (side-effect webhooks, mutating webhooks absent from snapshot).
4. **No format migration**: read Helm values (common + per-env overlays), Kustomize overlays, .env/Compose; schema from values.schema.json when present, else infer from template usage + rendered-output schema; plugins refine. CUE evidence: migration rejected even when pain is agreed.
5. **Validate the rendered result, not just values**: run the controller's render pipeline (helm template with Application/HelmRelease value stack, kustomize build), diff against snapshot's last-known live state, emit the diff in the PR (Octopus #20).
6. **Integrate with GitOps, don't replace it**: read Argo Application/ApplicationSet and Flux Kustomization/HelmRelease from the snapshot to map values files to cluster/namespace; write back as branch + PR with report attached; never sync directly.
7. **Three surfaces, one core**: pre-commit hook + CI mode (drop-in for yamllint+kubeconform+conftest, reliable exit codes unlike kyverno-cli pitfall); local UI with schema-driven forms (mandatory fields first, most-common next); JSON report for PR comments.
8. **Loop under seconds**: snapshots cached locally; no network at validation time; beat the 10-minute-CI bar from below.
9. **Env drift first-class**: evaluate the same change against every environment's snapshot (quotas, policies, CRD versions, image tags) and show a matrix — nearly half of enterprises run 4+ envs.
10. **Plugin depth**: plugins for policy engines (Kyverno, Gatekeeper/OPA, VAP/CEL — three evaluators), snapshot importers (k8s, Compose/Docker, registries, Vault/ESO for secret existence), values-schema inference per packaging tool (Helm, Kustomize, Compose). Core owns YAML/KYAML parsing, schema validation, snapshot format, reporting, Git/PR writing. gRPC process plugins justified only for foreign runtimes (Rego, WASM); prefer in-process Go interfaces plus a WASM extension point (Helm 4's choice).
11. **Emit KYAML or JSON** for rendered manifests/modified values written to Git; round-trip YAML preserving comments/ordering in values files for reviewable PR diffs.
12. **Quota as snapshot arithmetic**: used + delta <= hard, severity Warning when usage is stale — the one class where offline is inherently approximate.
13. **Instrument around outcome metrics** (change failure rate, rework rate, MTTD): count Blocking findings caught pre-push per PR and surface it — the only evidence that convinces platform teams to adopt another validator.
