# k8s-2026-features-and-trends

## State of the slice (verified 2026-09-12)

**Platform.** Kubernetes is at v1.37.0 ("Garhwal", 2026-08-26, 67 enhancements: 16 stable/23 beta/27 alpha); supported lines 1.34 (EOL 2026-10-27), 1.35 (2025-12-17), 1.36 (2026-04-22; Cloudsmith's 2026-03-12 date conflicts, trust kubernetes.io), 1.37; 1.38 in development. Admission has finished migrating to in-process CEL: ValidatingAdmissionPolicy GA since 1.30 (`admissionregistration.k8s.io/v1`; matchConstraints, matchConditions, variables, validations{expression,message,messageExpression,reason}, auditAnnotations, paramKind; bindings with validationActions Deny|Warn|Audit). MutatingAdmissionPolicy (KEP-3962) alpha 1.32 → beta 1.34 → **stable 1.36** (v1; patchType ApplyConfiguration (SSA merge) or JSONPatch; reinvocationPolicy; paramKind/bindings). CRD validation ratcheting (KEP-4008) GA 1.33. Declarative Validation for native types (KEP-4153, `+k8s:validation:` markers → validation-gen, ~18k lines of Go validation replaced) GA 1.36, and the release blog states rules are published in OpenAPI so clients can validate offline. Manifest-Based Admission Control (KEP-5793: `AdmissionConfiguration.staticManifestsDir`, strict decoder, object names must end `.static.k8s.io`) alpha 1.36 → beta 1.37 — policies living as files on the control plane, likely not API-discoverable. PSA stable since 1.25 (`pod-security.kubernetes.io/{enforce,audit,warn}[-version]` namespace labels, privileged/baseline/restricted, static exemptions). SSA (stable 1.22) is default in Helm 4 and Flux helm-controller; managedFields conflicts and `--force-conflicts` are now a first-class ops concern. kubectl KYAML output stable 1.37; kuberc beta 1.36; CBOR serializer beta 1.37. Gateway API v1.6.2 (2026-09-03; TCPRoute/UDPRoute GA in 1.6.0; CORS filter, client cert validation standard); Ingress API feature-frozen, ingress-nginx retired 2026-03-31, ingress2gateway 1.0 shipped. Kustomize is quiet: v5.8.1 (2026-02-09, Helm 4 compat fix), no 6.0 in sight.

**Packaging/delivery.** Helm 4.0.0 released 2025-11-12; current 4.3.0 (2026-09-09); Helm 3.22.0 (2026-09-10) is the last feature release, security patches until Feb 2027. Helm 4: OCI-by-default with digest installs (`oci://…@sha256:`), SSA default for new releases (`--force-replace`, `--rollback-on-failure`), kstatus waits, multi-doc values files, `--set-json`, reproducible archives (SOURCE_DATE_EPOCH), stable Go SDK, experimental chart apiVersion v3, plugin rewrite with optional Wasm runtime (go.mod: extism/go-sdk + wazero), post-renderers and template functions as plugins; values.schema.json via santhosh-tekuri/jsonschema/v6. Argo CD 3.5.2 (2026-08-27; no 3.6 RC): Source Hydrator beta (drySource → commit-server renders and pushes to syncSource or a `hydrateTo` staging branch; git notes under refs/notes/source-hydrator; Git-only, no OCI, no secret injection), `sourceIntegrity.required` commit-signature enforcement (alpha), internal mTLS, ApplicationSet UI, impersonation beta, Helm 4 with Helm 3 fallback, Gateway API health. Flux 2.9.5 (2026-08-31): 2.8 (Feb 2026) brought Helm 4 in helm-controller (SSA + kstatus + CEL health checks + `.status.inventory`, `UseHelm3Defaults` gate), cosign v3, ArtifactGenerator for charts, PR-comment notification providers; 2.9 (2026-06-30) introduced the **Flux CLI Plugin System** (`flux plugin install schema@sha256:…`, OCI-distributed binaries in `~/fluxcd/plugins`; official plugins Mirror, Schema, Operator), SSA ignore rules, SSH commit signing, custom Sigstore trusted roots for air-gapped keyless. "Gitless GitOps" is mainstream: `flux push artifact` (`application/vnd.cncf.flux.content.v1.tar+gzip`), `docker compose publish` produces the Compose equivalent; Argo supports OCI sources but not in the hydrator. Signing has standardized on Sigstore bundles: cosign v3.1.3 (2026-08-06; v2.6.5 maintained in parallel) requires `--bundle` (`.sigstore.json`, mediaType `application/vnd.dev.sigstore.bundle.v0.3+json`) as OCI 1.1 referrers; SLSA 1.2 (Build + Source tracks) uses in-toto/DSSE attestations; ORAS 1.3.4 is the generic client.

**Validation practice and whitespace.** Dominant 2026 practice remains "render, then lint in CI": `helm template | kubeconform` (v0.8.0), `kustomize build | flux schema validate`, `kyverno apply` / `gator test`, and `kubectl apply --dry-run=server` when a cluster is reachable. The July 2026 shift is **Flux Schema + Ecosystem Schema Catalog** (fluxcd/flux-schema v0.13.0, Apache-2.0; controlplaneio-fluxcd/schema-catalog, AGPL-3.0, rebuilt daily): offline validation with API-server structural-schema semantics *and* CEL `x-kubernetes-validations`, `flux schema extract crd` from live clusters, per-minor catalog snapshots (`/catalog/versions/kubernetes/v1.35`), and a public auth-less MCP server (`https://schemas.fluxoperator.dev/mcp`). Timoni 0.34 (2026-08-30) does the same for CUE (`timoni mod vendor crds` → cue.mod/gen, `timoni mod vet`). Nobody in OSS evaluates admission policies (VAP/MAP/Kyverno/Gatekeeper/Kubewarden/PSA) plus quotas/LimitRanges/discovery together against a snapshot; policy CLIs test only their own language; only server dry-run exercises webhooks. UI-driven validated value editing is the thinnest market: Monokle unmaintained, Datree archived 2024-06, Kubevious dormant since 2022, Cyclops stalled (last release 2025-07 RC, no GitOps write-back), Glasskube archived (pivoted to Distr), Weave GitOps RC-only since 2025. Living options are commercial/opinionated: Devtron 2.2.0, Qovery, Akuity (Kargo 1.11 has `yaml-update`, `helm-update-chart`, `git-open-pr`, `argocd-update` but no validation step), Codefresh (now Octopus), and Argo's Parameters tab ("dev/test only", overrides outside Git unless `.argocd-source.yaml`). AI ops is real but read-mostly: every major project shipped an MCP surface (Argo CD MCP v0.9.0, Flux Operator MCP read-only, Red Hat kubernetes-mcp-server, kubectl-ai, k8sgpt, Headlamp, kagent, HolmesGPT); Flux/Timoni/fluxcd/agent-skills ship SKILL.md skills; the Flux post reports 4/4 vs 1/4 task success and 57% fewer tokens with the schema MCP. Qovery frames the 2026 bottleneck as "policy engine, PR preview, audit trail and rollback"; CNCF's Platform Engineering Maturity Model places self-service UIs at Level 3 and transparently integrated guardrails at Level 4. Direction: schemas and CEL rules are becoming portable artifacts, making an accurate "pseudo cluster" feasible without a fake apiserver; policy engines converge on CEL (VAP, MAP, Kyverno ValidatingPolicy GA in 1.19 with VAP autogen, Gatekeeper K8sNativeValidation); plugin systems converge on Wasm (Helm 4 Extism, yoke, Kubewarden) or OCI-distributed binaries (Flux plugins, Kargo custom steps, Compose providers) rather than gRPC sidecars. The whitespace: a Git-first, cluster-snapshot-driven editor+validator that composes existing engines.

## Pain-point evidence

- Values validated only after commit → pipeline → sync; hydrator failures set `status.sourceHydrator` Failed and retry ~2 min; Kargo has no validation step (argo-cd.readthedocs.io source-hydrator; docs.kargo.io promotion-steps).
- Argo Parameters tab is "intended for dev/test"; persists only via `.argocd-source.yaml` (argo-cd.readthedocs.io parameters).
- Linters/policy CLIs siloed; none cover PSA, quotas, LimitRange, webhooks, API availability; kubectl-validate abandoned at 1.27 (fluxcd.io 2026/07 flux-schema-validation; gatekeeper gator docs; kubectl-validate repo).
- Only `--dry-run=server` exercises webhooks/real admission, needs credentials/RBAC; KEP-5793 moves policies into files (kubernetes.dev KEP-5793; VAP docs).
- Helm values contracts weak: optional schema, draft-07 docs, no strict/unknown-key handling (helm.sh charts; losisin repo).
- SSA ownership conflicts across Helm 4/Flux/Argo/MAP are a new failure class (fluxcd.io 2026/02 v2.8.0; MAP docs).
- Agents write YAML faster than review; "policy engine, PR preview, audit trail, rollback become the bottleneck"; schema MCP 4/4 vs 1/4 (qovery.com blog; flux-schema-validation blog).
- Prior UI attempts died: Monokle, Datree (2024-06-06), Cyclops (GitOps never shipped), Kubevious (respective GitHub repos).
- `docker compose config -q` checks schema only, not engine capabilities or variable presence (docs.docker.com compose config; provider-services).
- CRD churn breaks "valid last month" manifests without minor-pinned schemas; Flux 2.8/2.9 removed v1beta2 requiring `flux migrate` (opensource.googleblog.com ingress-nginx; fluxcd.io v2.9.0).

## Design implications

1. **Snapshot = versioned, signed OCI artifact**: server version; discovery incl. preferred versions; /openapi/v3 per group-version; full CRD YAML (keeps x-kubernetes-validations, defaults, ratcheting); VAP/MAP + bindings + param resources; webhook configs as opaque "cannot evaluate offline" markers with matchRules; namespaces with PSA labels; ResourceQuota, LimitRange, NetworkPolicy defaults; GatewayClass/IngressClass/StorageClass/PriorityClass/RuntimeClass names; Kyverno/Gatekeeper/Kubewarden policy objects and sync config; provenance (who/when/cluster identity); staleness TTL and diff on re-import.
2. **Embed upstream engines**: k8s.io/apiextensions-apiserver structural schema + k8s.io/apiserver/pkg/cel (or vendor/shell out to flux-schema and consume catalog snapshots pinned to the minor); k8s.io/pod-security-admission; small VAP/MAP evaluator (or Kyverno CLI `--parameter-resource`); kyverno apply / gator test / kwctl run as subprocesses; quota/LimitRange arithmetic over rendered manifests (unique, no OSS does it). Findings in PolicyReport shape, Info/Warning/Blocking mapped from Audit/Warn/Deny and audit/warn/enforce.
3. **Simulate mutations first** (MAP v1, Kyverno MutatingPolicy; ApplyConfiguration via SSA merge, JSONPatch) before validation to avoid false results; show mutated diff as "what the cluster will store".
4. **Two-tier confidence**: "offline-verified" vs "requires live dry-run" (webhooks, static policies, live quota usage); optional `--dry-run=server` stage with kubeconfig context; record tier per finding.
5. **Git-native, renderer-agnostic values**: values live in files the pipeline already reads (Helm values, Kustomize patches, kro instance spec, Timoni values.cue, Compose .env/override); render in-process (Helm 4 SDK, kustomize/api, compose-go, optional CUE); never a parallel values store; write back via commit/PR (Kargo git-open-pr, Argo hydrateTo).
6. **Form derived from existing contracts**, priority: values.schema.json (2020-12/draft-07) → `# @schema` annotations → kro SimpleSchema → Timoni `mod show config` → CRD OpenAPI → compose `config --variables` → inferred types; YAML round-trip preserving comments/order.
7. **Plug into existing control points**: GitHub/GitLab check + PR comment (Flux 2.8 providers, Argo hydrated branches); Kargo custom-steps container; pre-commit hook; CI action; Flux CLI plugin shim and/or kubectl plugin.
8. **Sign outputs** with cosign v3 bundles + referrers and an in-toto/SLSA predicate "validated against snapshot <digest>" so Flux verify / Kyverno ImageValidatingPolicy / Kargo can gate.
9. **Narrow, sandboxed plugin surface**: (a) Wasm via wazero/Extism for validators/transforms with no host access; (b) OCI-distributed binaries with JSON/stdio protocol for renderers/exporters/stores. hashicorp/go-plugin gRPC is no longer the norm; if retained, limit to one "engine" type and make everything else data-driven (schemas, CEL, policies). Distribute as signed OCI with `name@sha256:…` pinning.
10. **MCP server** (stdio + streamable HTTP, loopback bind, read-only default, token separated from cluster credentials) with tools validate, explain, diff, import_snapshot; publish SKILL.md skills (`gh skill install`, npx skills add, Claude Code plugin).
11. **Compose first-class** with its own snapshot: Engine/Compose version, `docker-<type>` binaries, GPU/runtime, model runner, secrets/configs existence; validate via compose-go, optionally `docker compose config -q`/`--dry-run`; publish via `docker compose publish`.
12. **Pin schemas to exact minor**, warn on skew (removed APIs, Ingress → Gateway); reuse `catalog/versions/kubernetes/vX.Y` layout.
13. **No desktop/Electron IDE or freeform YAML editor**; localhost/web UI over a Git worktree with strict values form + rendered preview + findings panel; headless CLI/CI parity is the primary contract.

## Uncertainties

- cosign v3.0.0 exact release date not retrieved (GoReleaser migration post 2025-11-05 suggests late Oct/early Nov 2025); v3.1.3 verified.
- Helm 4 JSON Schema draft support: library supports 2020-12, docs show draft-07; confirm accepted `$schema` URIs in 4.3.
- Whether `*.static.k8s.io` manifest-based policies are API-listable in 1.37 beta — likely not.
- Kyverno CLI offline coverage of MutatingPolicy/ImageValidatingPolicy and how far `--context-file` substitutes apiCall contexts.
- kubectl-validate CEL support undocumented (treat as no); flux-schema's "same engine" parity is self-reported — spot-check with Gateway API CRDs.
- Cyclops abandonment inferred from dates (last push 2026-01-22), no notice.
- Kubernetes 1.36 release date: Cloudsmith says 2026-03-12; kubernetes.io/endoflife.date say 2026-04-22 (trusted).
- Argo CD MCP canonical location (argoproj-labs/mcp-for-argocd vs akuity/argocd-mcp) unconfirmed.
- Argo CD 3.6 timing, hydrator OCI support, commit-server signing ("alpha, v3.6+").
- Commercial competitors (Akuity, Qovery, Octopus/Codefresh, Devtron enterprise) may have hidden UI value editors with policy gates; Devtron lock/approval docs 404.
