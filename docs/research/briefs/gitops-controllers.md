# gitops-controllers

## State of the slice (Sept 2026)

Two mature, CNCF-graduated pull-based controllers dominate and are not being replaced: Argo CD v3.5.2 (2026-08-27; 3.5.0 GA 2026-08-04; 3.4.x/3.3.x still patched) and Flux v2.9.5 (2026-08-31; 2.9.0 GA 2026-06-30; Helm v4 + SSA default since 2.8; all v1beta2 APIs removed, `flux migrate` required). The action has moved one layer up (promotion: Kargo v1.11.4 2026-09-03; Flux Operator ResourceSets) and one layer down (what is in Git: the "rendered manifests"/source-hydrator pattern). Progressive delivery is a separate, stable-but-slow layer: Argo Rollouts v1.10.0 (2026-08-27) and Flagger v1.45.0 (2026-09-01). Weave GitOps is dormant (last GA v0.38.0 Dec 2024, RCs only since).

Values live on one trunk branch, one folder per environment: (a) Helm values files layered `common → variant → env`, referenced from Argo `Application.spec.source.helm.valueFiles/valuesObject/parameters` or Flux `HelmRelease.spec.values/valuesFrom(ConfigMap|Secret, valuesKey, targetPath)`; (b) Kustomize overlays with small strategic-merge patches (`version.yml`, `replicas.yml`, `settings.yml`) plus Flux `postBuild.substitute/substituteFrom` `${VAR}`; (c) ApplicationSet git-files generator `config.json/yaml` per env. Branch-per-env is explicitly an anti-pattern (Codefresh/Octopus, Akuity, cloudogu, Red Hat). Promotion = copying a file between env folders (or Kargo doing it via `yaml-update`/`kustomize-set-image` + `git-commit`/`git-open-pr`). A growing minority stores values/manifests as OCI artifacts (`flux push artifact`, Flux OCIRepository, Argo OCI sources).

Pre-merge validation is almost entirely CI bolt-ons: `helm template`/`kustomize build`/`flux build kustomization --dry-run` → kubeconform → kyverno CLI/conftest/kubewarden → optional rendered diff (argocd-diff-preview with kind+Argo CD; `argocd app diff --local --server-side-generate`; `flux diff kustomization --path` = real server-side dry-run against live cluster). All opt-in, need cluster creds or an ephemeral cluster, and lose cluster context (namespace labels, existing resources, admission mutations, quotas, CRD versions). Controllers validate only at reconcile: Argo CD `kubectl apply --dry-run` client-side (or SSA dry-run with `ServerSideApply=true`; `Validate=false` opt-out); since 3.4 diffs use server-side dry-run so admission webhooks/CEL VAPs fire at diff time — but NOT for newly created resources; Flux kustomize-controller does SSA dry-run every interval. First true policy/quota/CRD check is post-merge. Post-merge feedback: Argo polls every 3 min (`timeout.reconciliation`, jitter 60s) unless `/api/webhook`; ApplicationSet git generator 3 min, PR generator 30 min (`requeueAfterSeconds: 1800`); Flux `spec.interval` (≥30s, commonly 1–10 min) or Receiver webhooks; kustomize-controller worst case 2×`spec.timeout`. Realistic push→known-broken: 1–15 min. Rollback canon is `git revert`; `argocd app rollback [ID]` (from `revisionHistoryLimit`, needs auto-sync off), Flux `HelmRelease.spec.upgrade.remediation` (`rollback`/`uninstall`, `remediateLastFailure`), and Rollouts/Flagger aborts roll back in-cluster WITHOUT touching Git (divergence that selfHeal then fights).

Direction: (1) rendered manifests everywhere — Argo Source Hydrator (beta 3.5) writes hydrated YAML to `syncSource.targetBranch` or a `hydrateTo` staging branch, state in git notes `refs/notes/source-hydrator`; (2) SSA + SSA-dry-run diffs as truth, CEL health (`healthCheckExprs`, `dependsOn[].readyExpr`); (3) promotion as a CRD layer (Kargo Warehouse/Freight/Stage/Promotion, 70+ steps, REST-only from v1.12; Flux Operator ResourceSet/ResourceSetInputProvider); (4) shift-left schema tooling productised — Flux 2.9 CLI plugin system with official `schema` plugin (JSON Schema + CEL, bundled K8s/OpenShift/Gateway-API/Flux schemas, "field index for AI agents"), Argo 3.5 ApplicationSet "Preview Apps" tab; (5) "config-as-data" SaaS (ConfigHub, Brian Grant) with validation functions and "apply gates" — closest competitor. Whitespace: no editor knows the values-file schema, holds a snapshot of the target cluster's admission policies/quotas/CRDs/webhooks, and emits a PR into the env folder with hydrated diff without live creds at edit time.

## Pain-point evidence

- First real validation is post-merge: Argo SSD "skips newly-created resources… Admission Controller validation won't catch issues during initial resource creation"; Flux does "server-side apply dry-run… at each interval" (argo-cd diff-strategies docs; fluxcd kustomizations docs).
- Previews need creds or ephemeral clusters: "you need to provide your CI pipeline with credentials that access the cluster where Argo CD is installed… when you have multiple clusters, it's unclear which cluster you should pick" (codefresh.io/blog/argo-cd-preview-diff; argocd-diff-preview docs).
- No first-party HelmRelease values preview: `flux diff` has only `artifact` and `kustomization` (fluxcd.io/flux/cmd/flux_diff/).
- Policy CLIs silently pass: kyverno CLI v1.12.x printed "FAIL: 1" with exit 0; "cannot evaluate namespace-scoped resources or variable substitution that occurs at admission time" (dev.to/sodiqjimoh).
- Slow polling feedback: 3-min Argo poll; PR generator 1800s; Flux interval >30s, max reconcile 2×timeout (Argo webhook docs; PR generator docs; flux-e2e).
- Reviewers see parameter diffs not applied YAML: "Git doesn't show what's actually deploying… promotion decisions lack concrete manifest context" (akuity.io rendered-manifests).
- selfHeal re-applies bad merges every ~3 min and reverts hotfixes (dev.to Argo CD rollback checklist).
- git revert incomplete: "database migration conflicts, PVC data divergence… doesn't affect Helm's internal release history" (medium.com/kotaicode).
- In-cluster rollbacks diverge from Git: Flagger "scales the canary deployment to zero without modifying Git" (docs.flagger.app; Rollouts docs).
- Branch-per-env still common yet "often discouraged / anti-pattern" (akuity whitepaper; cloudogu/gitops-patterns).
- Argo internals break on minor upgrades: 3.3 git notes ("Automations relying on commits as signals should consult the new git note namespace"); 3.5 gRPC clients "must be regenerated" (upgrading 3.2-3.3, 3.4-3.5).
- Effective value hard to compute across merge layers (Flux helmreleases docs; octopus.com env modelling).
- Helm typing/missing valuesFrom fail only at reconcile (`optional`, `literal` flags exist for this); Argo 3.5 Helm 4 "silently drop the plain HTTP flag" surprises.
- Imperative overrides (`argocd app set`, UI) drift from Git; 3.3 anonymous Settings API hides resourceOverrides.

## Design implications

- Git is the only write target: "apply" = open PR / push commit to env folder or hydrated branch; never apply to cluster. Emit hydrator.metadata-style provenance (drySha, author, references) and Kargo-style commit trailers.
- Discover the values model from controller CRs: Argo `source(s).helm.{valueFiles,valuesObject,parameters,fileParameters}`, `kustomize.{images,replicas,patches}`, ApplicationSet git-files globs, `sourceHydrator.drySource`; Flux `HelmRelease.spec.{values,valuesFrom,chart.spec.valuesFiles}`, `Kustomization.spec.postBuild.substitute(From)`, images, patches. Map each key to file+path+merge layer; show effective value per documented merge order.
- Support natively: folder-per-env on trunk, app-of-apps/ApplicationSet-generated, rendered-manifest branches (`env/<name>` or hydrateTo). Branch-per-env read-only/legacy.
- Pseudo-cluster snapshot must capture what CI misses: server version + API discovery (incl. deprecated), CRD OpenAPI schemas, Namespaces with labels/annotations, ResourceQuota/LimitRange, ValidatingAdmissionPolicy(+Bindings) CEL, Kyverno ClusterPolicy/Policy, Gatekeeper ConstraintTemplates/Constraints, Validating/MutatingWebhookConfiguration metadata (warn "cannot emulate"), PodSecurity labels, Storage/Ingress/GatewayClasses, existing Secret/ConfigMap names for lookups, and the GitOps CRs. Versioned, signed, redactable, air-gap importable.
- Validation pipeline: render (helm template / kustomize build / `flux build kustomization --dry-run` / Argo `manifestsWithFiles`) → schema (kubeconform-style with snapshot CRDs; consider Flux `schema` catalog format) → policy (embed Kyverno or shell out with snapshot context; VAP CEL via k8s libraries; Gatekeeper via OPA) → quota/limit arithmetic → immutable-field diff vs snapshot → semantic checks (image tag exists, referenced Secret/ConfigMap present). Keep Info/Warning/Blocking; admission deny → Blocking, audit/warn → Warning.
- Optional "live check" when creds exist: Argo `server-side-diff`, `manifestsWithFiles`, sync `{dryRun:true}`; `flux diff kustomization --path`; `kubectl --dry-run=server`. Label snapshot vs live findings; never require it.
- Fill concrete gaps: HelmRelease values-diff preview, admission checks for NEW resources, quota arithmetic (nobody), effective-value explorer, snapshot-based diff needing no cluster.
- Post-merge feedback: subscribe to Argo app status (REST/gRPC watch, Notifications) or Flux commit-status/PR-comment providers; show expected vs actual; optionally fire `/api/webhook` / Flux Receiver to skip the poll.
- Rollback = revert PR with awareness of non-revertible effects (Helm hooks/Jobs, StatefulSet/PVC fields, CRD schemas, immutable fields); surface `argocd app rollback`/Flux remediation as in-cluster counterpart; warn about selfHeal.
- Plugin depth: ecosystem uses (a) OCI-distributed CLI plugins with pinned digests (Flux 2.9), (b) container steps (Kargo), (c) go-plugin RPC (Rollouts), (d) CRDs/HTTP. Recommendation: keep signed-OCI distribution, reduce plugin TYPES to two — "source adapters" (Argo/Flux/Compose/Kargo discovery + PR writing) and "validators" (schema/policy/quota) — subprocesses with small JSON/gRPC contracts; built-ins compiled in (Vault-style) for Helm/Kustomize/Kyverno/VAP. UI and store become core, not plugins.
- Integrate with Kargo: zhi as a PromotionTask container (non-zero exit fails Promotion); open the PR `git-wait-for-pr`/`git-merge-pr` wait on; read Freight/Stage to show next promotion target.
- Rendered-manifests awareness: validate hydrated YAML when sourceHydrator or `env/*` branches exist; read `refs/notes/source-hydrator` for drySha, not commits; gate hydrateTo→syncSource.
- Docker Compose: no controller; `docker compose config` + compose-spec schema + host snapshot (docker version, networks, volumes, env); apply via Git push + Watchtower/Portainer/Komodo/CI (verify in another slice).
- Version-pin renderers from the snapshot (Helm 4.2 vs 3.19, Kustomize 5.8, K8s API versions); defaults changed recently (Argo 3.5 Helm 4 OCI strictness, Flux 2.8 SSA, Argo 3.4 SSD).
- Expose zhi as API/MCP surface: GitHub Check Run / PR comment (like `githubpullrequestcomment`), Argo Notifications webhook target.
