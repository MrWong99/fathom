# docker-compose-landscape

## State of the slice (Sept 2026)

The Compose Specification is the de facto single-host application model. Docker Compose is at v5.5.1 (2026-09-03), reference parser compose-go at v2.15.0 (same day); both ship monthly. compose-go (`github.com/compose-spec/compose-go/v2`, Apache-2.0, go 1.24, 444 stars) is the load-bearing library: Docker Compose, nerdctl, kompose (v1.38.0 on compose-go v2.10.0), Tilt, Uncloud, and Docker Language Server (compose-go v2.10.2 + santhosh-tekuri/jsonschema v6) all consume it. Pipeline: YAML parse (go.yaml.in/yaml/v4) -> include/extends -> interpolation (`template.Substitute`; `${VAR:-def}`, `${VAR:?err}`, `${VAR:+alt}` etc.) -> JSON-Schema draft 2020-12 validation (`schema/compose-spec.json`, `additionalProperties:false` on services, `patternProperties ^x-` everywhere, near-universal `description`s) -> normalization -> ~28 consistency checks (`loader/validate.go`) -> `types.Project`. Every step is skippable via `loader.Options` (SkipValidation, SkipInterpolation, SkipConsistencyCheck, SkipResolveEnvironment, SkipInclude, SkipExtends, SkipNormalization); `cli.WithExtension` binds typed Go structs to `x-*`; `template.ExtractVariables` enumerates variables with default/required flags (what `docker compose config --variables` prints). The schema is already good enough to drive a generated form; what is missing is everything that depends on the target host.

Dominant parameterization practice: one `compose.yaml` (+ auto-merged `compose.override.yaml`), `.env` for interpolation (precedence shell > `--env-file` > `.env`), `env_file:` per service (`required: false` since 2.24, `format:` since 2.30), multi `-f`/`COMPOSE_FILE` merge rules (mappings merge, sequences append, `!reset`/`!override`, ports keyed by ip/target/published/protocol, volumes by target), `profiles`, `include` (conflicts are errors), `extends` (no cycles, referenced volumes/networks/secrets not auto-imported), `x-` anchors. Unset variables silently become "" (only `:?` is fatal) — the most common "typo in env" failure. Docker's production guidance remains `-f compose.yaml -f compose.production.yaml up -d` over DOCKER_HOST/context; CI is `docker compose config -q` then pull/up over SSH, with community actions (docker/setup-compose-action, hoverkraft-tech/compose-action v3.1.0), not controllers.

GitOps-for-Compose is real but fragmented and UI-first. Portainer (2.45.0 STS / 2.39.7 LTS, Aug 2026) has Git-backed stacks with polling/webhook, Edge Stacks with staggered rollouts (BE), and BE-only fleet-wide Docker security policies — the only host-level policy concept in the slice, enforced at deploy time inside Portainer, not exportable. Komodo (v2.3.3, Rust, GPL-3) is most Git-native: TOML `[[stack]]` resources synced by a ResourceSync that diffs and shows pending changes. Coolify (v4.3.19) and Dokploy (v0.30.6, Swarm-based) are Heroku-style PaaS that ingest Compose but rewrite it; neither validates beyond running. Uncloud (v0.20.0, pre-1.0) is multi-machine Compose over WireGuard with `x-*` extensions and a plan before apply. Kamal (v2.12.0) avoids Compose entirely. Watchtower was archived 2025-12-17; successors are nicholas-fedor/watchtower (v1.22.1) and WUD (9.0.2). Swarm is not deprecated but stable-not-growing (Mirantis promises muddied by IREN acquisition May 2026; Engine 29 nftables mode not yet usable on Swarm). Podman 6.1.1 pushes Quadlet; `podman compose` delegates to docker-compose or podman-compose (v1.6.0, partial spec). Compose Bridge is now `docker compose bridge convert` with container-image transformers. Compose itself is absorbing plan/diff (v5.2+ reconciliation), packaging (`publish` -> OCI), extension (`provider:` services, `models:`, transformers) and IDE validation. Nobody offers offline validation of a Compose model against a snapshot of the target host: port conflicts, missing bind sources, nonexistent tags, empty-substituted variables, `deploy.*` ignored outside Swarm, cross-project `container_name` collisions, capacity, and policy are all discovered at `up` or later. Linting is thin (DCLint v3.1.0, KICS, Conftest; Trivy does not list Compose). That gap — host/fleet snapshot + policy + compose-go model, checked before push — is the whitespace for the zhi rewrite.

## Pain-point evidence

- Unset variables silently become "" -> `image: postgres:` invalid only at `up`; only `${VAR:?}` fatal (docs.docker.com variable-interpolation).
- `.env` edits not applied on `restart`; values baked at creation; need `down`+`up` (blog.gntech.me 2026-05-24).
- Port conflicts ("Bind for 0.0.0.0:3000 failed: port is already allocated"), missing bind sources ("bind source path does not exist"), pull/auth, healthcheck-gated depends_on, OOM are runtime-only; `config -q` cannot see them (oneuptime.com 2026-02-08).
- Undeclared named volumes and port numbers outside 1-65535 from typos are common (devbolt.dev).
- Relative paths in override files resolve relative to the FIRST `-f` file, silently breaking env_file/binds (docs.docker.com merge how-to).
- `deploy.*` silently ignored by Compose; `extends` and environment secrets unsupported by `docker stack deploy` — same file behaves differently per target (docs.docker.com services reference).
- `x-` fields never validated; `x-port` vs `x-ports` typos pass (docs.docker.com extension).
- Watchtower abandoned Dec 2025; forks "full of AI slop"; auto-update diverges from Git (containrrr discussion #2135).
- PaaS rewrite Compose (`coolify.managed=true`, proxy labels); "Raw Compose Deployment" needed to escape (coolify.io docs).
- Host policy exists only as Portainer BE deploy-time enforcement (edge agent >=2.37), not portable (docs.portainer.io policies).
- Converters lose fidelity: Bridge drops `develop.watch`; podlet lacks interpolation; podman-compose partial (github.com/containers/podlet).
- Swarm strategic uncertainty despite no deprecation (blog.oxyconit.com 2026 guide).
- CI validation ad hoc: `config -q` in pre-commit/Actions; linters tiny (blog.devinsmith.co.za).

## Design implications

1. Embed compose-go v2 (`cli.NewProjectOptions` + `LoadProject`) as THE Compose model; never hand-roll merging. Load with `WithInterpolation(false)` to run `template.ExtractVariables` (editable value set with defaults/required), then reload with the UI `Mapping` for the resolved `types.Project`; run `schema.Validate` + `checkConsistency` and map errors to Blocking with field paths.
2. Add "strict interpolation" compose-go lacks: variable referenced but absent -> Blocking (Warning if defaulted); flag empty results for `image`, `ports`, `volumes` sources; validate image refs with distribution/reference (already a dependency).
3. Define a Compose pseudo-host snapshot as JSON importable from a live host in one read-only API pass: Engine/API version, OS/arch, cgroup version, userns-remap/rootless, seccomp/apparmor defaults, default-address-pools, CPU/mem/GPU, listening host ports (`docker ps` published + optionally `ss`), existing networks/volumes/containers/projects (`docker compose ls`), images with digests, registry auth reachability, bind-source existence/perms, swarm/podman flags. Same shape via Portainer API and Komodo Periphery.
4. Host-aware checks: published-port collision (vs snapshot and other services/projects), bind source missing, cross-project `container_name` collision, cpus/mem vs capacity, `gpus` without GPU, image tag not cached and registry unreachable (Info) or tag nonexistent (Blocking via HEAD manifest when online), `deploy.*` with swarm=false (Warning), Swarm-unsupported attrs when swarm=true, podman-compose-unsupported attrs when podman=true, version gates (Compose >=2.24 `env_file.required`, >=5.3 `pre_start`).
5. Policy as data, not plugins: policy pack format (Rego via OPA/Conftest or CEL) over normalized compose-go JSON; default pack mirrors Portainer security dimensions (no privileged, no host pid/net/ipc, binds only under allowed roots, no added capabilities, no sysctls, explicit tags/digests, healthcheck required, no `latest`) plus KICS queries. Snapshot may carry the host's pack so "import cluster policy" has a Compose meaning.
6. Keep Git canonical: never rewrite compose.yaml. Write values to `.env` / `compose.<env>.yaml` overrides and `x-zhi-*` blocks (typed via `WithExtension`) so plain `docker compose` still works; emit `config --hash`-equivalent hashes for drift detection.
7. Values with UI hints via known schemas: Portainer App Template `env` fields (name/label/description/default/preset/select) plus Dokploy helpers (password/base64/uuid/domain/randomPort) as value kinds; derive labels from Compose JSON-schema `description`s.
8. Target flavours explicit (docker-compose, swarm stack, podman-compose/quadlet, Uncloud) as a snapshot field switching attribute-support matrices; export Quadlet only from the post-interpolation model.
9. Shallow plugin depth: built-in Go importers (Docker API, Portainer API, Komodo) and checkers; for external extension copy Compose's provider protocol (exec binary, `metadata` parameter schema, JSON lines `info|error|setenv|debug`) instead of gRPC/go-plugin; reserve the container transformer contract (`/in/compose.yaml` -> `/out`) for exporters.
10. Fit existing GitOps loops: commit to the repo Portainer polls / Komodo syncs / CI deploys over SSH; optionally emit `docker compose publish`-style OCI artifacts with `--resolve-image-digests` as immutable release records.
11. Provide a plan view modelled on Compose v5.2+ reconciliation and Uncloud's plan: diff resolved model vs snapshot (containers recreated, volumes/networks changed) before push.

## Uncertainties

- Release dates resolved via `gh api` `published_at`, but Portainer LTS/STS numbering (docs 2.39.7 LTS / 2.44.0 STS vs GitHub tag 2.45.0) needs double-checking.
- Whether `docker compose bridge` works on Linux Engine without Docker Desktop not verified end-to-end.
- Whether `config` errors or only warns on unknown keys inside `x-` blocks untested (schema implies anything passes).
- `jobs` top-level element is in compose-go schema/checks but not in spec.md or Docker docs — in-flight/unstable.
- Provider services and `models` lack an "experimental" label, but `compose alpha` still lists `scale|watch|dry-run`; graduation is a moving target.
- Portainer CE vs BE feature gating not verified against the CE build.
- Checkov Compose support unchecked; Trivy no, KICS yes.
- Docker Language Server slowdown may mean IDE validation is moving elsewhere; no announcement found.
- Mirantis/IREN Swarm statements from a single blog synthesis; primary lifecycle pages not fetched.
- Uncloud extension list differs between release notes and docs.
- Human decisions: support Swarm at all; policy engine Rego vs CEL (one engine should serve both Compose and K8s slices).
