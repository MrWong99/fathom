# schema-validation-tech

**Dimension:** Schema and validation technologies for editor-time feedback on deployment values (JSON Schema Go libs, Kubernetes OpenAPI/structural schema + CEL offline, CUE, KCL, Rego, Kyverno, Starlark, Pkl, yaml-language-server/SchemaStore, Helm/Compose schemas, schema->form generation, vendor extensions, cross-field validation).

## State of the slice in 2026

JSON Schema draft 2020-12 is the de-facto interchange format for "what values are allowed" across the deployment stack. The Compose spec schema is authored in 2020-12 (`compose-spec.json`, `$schema https://json-schema.org/draft/2020-12/schema`, `patternProperties ^x-` for extensions); Helm 4 (v4.3.0, 2026-09-09) pins `github.com/santhosh-tekuri/jsonschema/v6 v6.0.3` in go.mod so `values.schema.json` is no longer capped at draft-07 (Helm 3-era issue #13069 was closed-not-planned; the docs page still shows draft-07 examples and is marked "not yet updated for Helm 4"); compose-go v2.15.0 (2026-09-03) and kubeconform also validate with santhosh-tekuri v6. yaml-language-server 1.24.0 (2026-07-07, MIT, ajv 8) validates draft-04/07/2019-09/2020-12 with editor feedback via the modeline `# yaml-language-server: $schema=<url|path>` (or IntelliJ-style `# $schema:`), the reserved `kubernetes` keyword with `yaml.kubernetesVersion`, and SchemaStore's `catalog.json` (name/description/fileMatch/url/versions; Apache-2.0). Dominant Go practice: santhosh-tekuri/jsonschema/v6 as validator (Apache-2.0, mixed dialects, custom `$vocabulary`, `RegisterFormat`, localization, `FlagOutput/BasicOutput/DetailedOutput` with `instanceLocation` + `keywordLocation` per spec section 12), with kaptinlin/jsonschema and google/jsonschema-go as alternatives; xeipuuv/gojsonschema is dead. invopop/jsonschema is reflection-only (Go type -> schema).

Kubernetes: the only faithful offline reproduction of apiserver acceptance is running the apiserver's own code, which kubernetes-sigs/kubectl-validate does: `pkg/validator` builds a structural schema from OpenAPI v3 (client-go `openapi.Client` backed by local dirs `/apis/<group>/<version>.json` and `/api/<version>.json`, `--local-crds` CRD YAML dirs, or a live cluster) and calls `customresource.NewStrategy(...)` + `rest.BeforeCreate`, whose Validate runs (1) OpenAPI schema validation (kube-openapi `validate.SchemaValidator`), (2) structural invariants (embedded resources, `x-kubernetes-list-type` map/set), (3) CEL `x-kubernetes-validations` via `k8s.io/apiextensions-apiserver/pkg/apiserver/schema/cel` v0.37.0 with `celconfig.RuntimeCELCostBudget` (CEL skipped when earlier errors are blocking), all returning `field.ErrorList` with field paths. The catch: native types (Deployment, Service...) are validated only by a best-effort OpenAPI replica of hand-written Go validation, and KEP-5073 (declarative validation via `+k8s:` tags; v1.33-1.36 rollout, beta enforcement planned 1.37-1.38, GA 1.39+) explicitly makes publishing those rules to OpenAPI a non-goal, so offline native-type validation stays approximate. Cheaper alternative: kubeconform (v0.8.0) against yannh/kubernetes-json-schema (daily auto-generated, `-standalone-strict` variants) and datreeio/CRDs-catalog (community; Datree the company is gone, datree.io 404s) — pure JSON Schema, no CEL, no list-type invariants.

Policies: every cluster-side engine now exposes an offline evaluator with uneven library ergonomics. CEL: cel-go (published as `cel.dev/cel-go` v0.32.0 2026-08-19 and `github.com/google/cel-go` v0.31.0 2026-08-07; repo moving to `github.com/cel-expr/cel-go` on 2026-06-16) plus `k8s.io/apiserver/pkg/cel/library` v0.37.0 (lists, regex, urls, ip, cidr, quantity, semver, format, authz, jsonpatch) and `k8s.io/apiserver/pkg/cel/environment` (`MustBaseEnvSet(version, strictCost)`, NewExpressions vs StoredExpressions) give exact parity with CRD rules and ValidatingAdmissionPolicy; `k8s.io/apiserver/pkg/admission/plugin/policy/validating` v0.37.0 exports a Validator producing `PolicyDecision{ActionAdmit|ActionDeny, EvalAdmit|EvalDeny|EvalError, Message, Reason}` but needs VersionedAttributes, params, namespace, and an authorizer stub. Kyverno v1.19.1 (2026-09-10): ValidatingPolicy `policies.kyverno.io/v1` stable since v1.19, CEL-based; `kyverno apply` evaluates ClusterPolicy, ValidatingPolicy, native VAP + bindings, and JSON payloads with mocks and PolicyReport output; Go packages `github.com/kyverno/kyverno/pkg/cel/{compiler,engine,libs,policies/vpol...}` are importable but drag in the whole module (with listed CVEs). kyverno-json (JMESPath assertion trees) is dormant standalone (v0.0.3 2024-05, last commit 2024-10-09), superseded by `kyverno json` (experimental, `KYVERNO_EXPERIMENTAL=true`) and ValidatingPolicy `spec.evaluation.mode: JSON`. OPA v1.20.2 (2026-09-03): `github.com/open-policy-agent/opa/v1/rego` embeds cleanly, wasm runtime is pure-Go wazero since v1.19, `json.match_schema`/`json.verify_schema` builtins exist; Gatekeeper `gator test/verify` evaluates ConstraintTemplates (Rego and CEL engines) offline. Configuration languages: CUE (`cuelang.org/go` v0.17.1, 2026-07-16) is the strongest Go-native cross-field option; KCL (`kcl-lang.io/kcl-go` v0.12.5) is CGO-bound; Starlark is scripting only; Pkl spawns an external `pkl` binary. Form generation: nothing Go-native; the standard is JSON Schema + separate UI schema in a JS renderer (RJSF 6.10.0, JSON Forms 3.8.0), with Backstage proving `ui:*` keys embedded in JSON Schema at scale. The whitespace: no single project combines schema-form UI, exact apiserver validation, and cluster policy evaluation before push.

## Pain-point evidence

- Native K8s validation cannot be reproduced exactly offline; kubectl-validate README calls OpenAPI "a best-effort replication"; KEP-5073: "It is not a goal of this KEP directly to publish validation rules to OpenAPI" (kubectl-validate README; KEP-5073 README).
- Helm schema tooling fragmented: #13069 closed-not-planned; Helm 4 go.mod quietly switched to santhosh-tekuri v6.0.3; docs unupdated; #7756 (lint ignores -f), #12994 (invalid schema passes lint).
- Cluster-data policies need mocks offline: Kyverno Resource/HTTP/ImageData/GlobalContext libs require cluster access; `kyverno apply` needs `--context-path`; gator referential constraints need `metadata.namespace` + synced data (kyverno.io cel-libraries, kyverno_apply reference; gatekeeper gator docs).
- Rego/Kyverno violations carry no JSON pointer unless the policy emits one; only JSON Schema output units and CEL `fieldPath`/`field.ErrorList` are addressable (pkg.go.dev opa/v1/rego; K8s CRD validation-rules docs; 2020-12 core).
- Form renderers default to draft-07; RJSF Ajv2020 "with noted breaking changes and limited testing" (RJSF validation docs).
- Reference offline validators lack releases: kubectl-validate v0.0.4 (2024-05-29) despite commits to 2026-01-05; kyverno-json last commit 2024-10-09; gojsonschema last release 2019 (pkg.go.dev; GitHub commit logs).
- KCL (CGO native lib) and Pkl ("spawning the pkl CLI as a child process") conflict with static single binaries (pkg.go.dev kcl-lang.io/lib; pkl-lang.org evaluation docs).
- CEL module-path churn (google/cel-go -> cel.dev/cel-go -> cel-expr/cel-go, move date 2026-06-16) risks duplicate modules when mixing with k8s.io/apiserver (cel-expr README; pkg.go.dev).
- Editor K8s YAML validation uses a bundled generic schema, not the user's cluster (no CRDs/CEL/policies) unless yaml.schemas is hand-maintained (yaml-language-server README).
- Live per-keystroke ajv validation is "expensive...with possibly strong impact on performances"; large schemas (compose-spec.json, CRD-derived) worsen it (RJSF validation docs).

## Design implications

1. Standardize on JSON Schema 2020-12 as value-schema interchange and santhosh-tekuri/jsonschema/v6 as in-process validator (matches Helm 4, compose-go, kubeconform verdicts). Compile once per workspace; validate whole tree per edit (sub-millisecond at values size).
2. Canonical error record = 2020-12 output unit (instanceLocation pointer + keywordLocation + message); convert every engine into it: apiserver `field.ErrorList`, CEL fieldPath/reason, Kyverno PolicyReport results (path via message convention), Rego violations (require policies to emit `path`). Severity: schema type errors -> Blocking; CEL/VAP/Kyverno Deny -> Blocking; Warn/Audit or best-effort native checks -> Warning; annotations -> Info.
3. Define the pseudo-cluster snapshot on disk exactly as kubectl-validate's openapiclient expects: `/api/<version>.json`, `/apis/<group>/<version>.json` (from `GET /openapi/v3`), a `crds/` dir, admission policies (VAP + bindings, Kyverno ClusterPolicy/ValidatingPolicy, Gatekeeper ConstraintTemplates/Constraints), namespaces/ResourceQuota/LimitRange objects, server version string. Import = one kubeconfig-authenticated dump; validate via kubectl-validate library. Reuse, do not reimplement.
4. Vendor/import kubectl-validate `pkg/validator` + `pkg/openapiclient` from main (no tags; Kyverno fork exists) for OpenAPI structural validation, list-type invariants, and CEL with real cost budget. Track k8s.io/apiserver minors (v0.37.0 now); pin `environment.MustBaseEnvSet` to the snapshot's cluster version.
5. CEL (cel-go + k8s.io/apiserver/pkg/cel/library) as the single rule language for plugin- and user-defined cross-field validators; expose `self`/`oldSelf`, plus `values` (flat tree) and `rendered` (manifests). Do not embed KCL (CGO) or Pkl (external binary); CUE only as optional import/export (cue get crd, encoding/jsonschema), not a runtime dependency.
6. Policy evaluation in two tiers: (1) in-process native VAP via `k8s.io/apiserver/pkg/admission/plugin/policy/validating` with a synthetic admission-attributes shim (CREATE/UPDATE, previous Git revision as oldObject); (2) out-of-process engines behind a "policy-evaluator" plugin interface: `kyverno apply --policy-report --output-format json --context-path <snapshot>` and `gator test --output json`. Do not import github.com/kyverno/kyverno as a Go dependency (weight, CVEs).
7. Form rendering: Go core stays schema-only; UI hints in a documented vendor vocabulary (x-ui-widget/ui:widget, x-ui-order, x-secret, x-component, x-help) ignored as annotations by 2020-12 validators; register it as a custom vocabulary in santhosh-tekuri so hints are type-checked. Render with RJSF (or JSON Forms if show/hide rules matter) using Ajv2020 explicitly; browser validation is advisory; push Go output units into `extraErrors`.
8. Reuse the JSON Forms rule model (SHOW/HIDE/ENABLE/DISABLE with a JSON Schema condition on another field's scope) for component toggles and conditional sections; composes with if/then/dependentSchemas.
9. Generate schemas when absent: Helm — infer from values.yaml with `# @schema` annotations, honour existing values.schema.json, replicate Helm 4's merged-.Values-vs-all-subchart-schemas before validating; Compose — derive values tree from `${VAR}` interpolation sites, validate rendered file with compose-go loader/`schema.Validate`.
10. Editor integration for free: write workspace schema to `.zhi/schema.json`, inject `# yaml-language-server: $schema=./.zhi/schema.json` into managed values files (or a local SchemaStore-format catalog); consider yaml.schemas entries for CRD-derived schemas from the snapshot.
11. Plugin depth: validation needs shallow plugins only — (a) JSON Schema fragment (Go providers via invopop/jsonschema + jsonschema_extras for x-ui), (b) CEL rules and optional CEL functions, (c) optional form widget id. Reserve gRPC plugins for value sources/stores/exports; policy engines and cluster importers fit exec-style adapters emitting output-unit JSON.
12. Be honest about certainty tiers in the UI: "schema-valid", "apiserver-valid (CRDs exact, native types approximate until KEP-5073, beta 1.37-1.38)", "policy-valid (offline-evaluable rules only; N skipped needing live data)". Offer server-side dry-run (`kubectl apply --dry-run=server`) as the final tier when a cluster is reachable.

## Uncertainties

- GitHub release/tag page dates were unreliable (years shifted: santhosh-tekuri v6.0.0 shown 2026, CUE v0.14.0 as 2024, kcl-go v0.12.5 as 2024); pkg.go.dev/npm dates preferred. kubeconform v0.8.0 year (2024 vs 2026) unresolved.
- Helm 4 accepting 2020-12 end-to-end is inferred from go.mod only; verify with `helm lint` on a 2020-12 chart.
- cel-go canonical module path post-move unconfirmed; check which path k8s.io/apiserver v0.37+ imports to avoid duplicate modules.
- KCL Rust core version parity (tags showed v0.11.2 vs kcl-go/lib v0.12.5) and cadence unconfirmed.
- CRD validation rules GA version: docs summary said 1.26 but looked synthesized; memory says 1.29 — verify in the 1.29 changelog. CEL cost budget (~1,000,000 units) unverified.
- OPA `json.match_schema` draft coverage (likely draft-07 via gojsonschema fork) and error shape unverified (builtins page 404).
- kube-openapi `validate.SchemaValidator` error path detail conflicting (summary: no field paths; memory: `errors.Validation` has dotted Name); kubectl-validate returns `field.ErrorList` regardless.
- google/jsonschema-go error type (instance path) and `$dynamicRef` support undocumented; MCP Go SDK usage partly from memory.
- JSON Forms 3.8.0 release date unknown; cadence unclear.
- Whether Kyverno `pkg/cel/policies/vpol` imports without cluster clients/informers unverified; CLI is the only confirmed offline route. v1.19 mock flags for HTTP/globalContext not inspected.
- Datree shutdown inferred from 404; CRDs-catalog per-CRD freshness unverified.
- Pkl implementation (Kotlin/JVM, GraalVM native CLI) from memory; irrelevant if not adopted.
- yannh/kubernetes-json-schema newest K8s version directory not visible (listing truncated).
- No Go-native JSON-Schema->form renderer found; templ/htmx options unchecked, so "UI must be JS or hand-rolled" is unverified.
