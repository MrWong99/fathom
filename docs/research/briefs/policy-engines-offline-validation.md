# policy-engines-offline-validation

## State of the slice (Sept 2026)

Kubernetes-native CEL admission is the centre of gravity. ValidatingAdmissionPolicy (VAP) is GA since 1.30; MutatingAdmissionPolicy (MAP) went alpha 1.32 / beta 1.34 / GA 1.36 (KEP-3962); Kubernetes 1.37.0 (2026-08-26, supported 1.34–1.37) adds beta "manifest-based admission control" (feature gate `ManifestBasedAdmissionControlConfig`, on by default) loading VAP/MAP + bindings from a `staticManifestsDir` on the apiserver, names suffixed `.static.k8s.io`, paramKind/paramRef forbidden, bindings must reference policies in the same file set. Every third-party engine has re-platformed on CEL: Kyverno 1.19 (2026-08-20; v1.19.1 2026-09-10) declares full parity for its CEL types (`policies.kyverno.io/v1` ValidatingPolicy, NamespacedValidatingPolicy, MutatingPolicy, GeneratingPolicy, ImageValidatingPolicy, DeletingPolicy) and deprecates ClusterPolicy with removal in 1.20 (~Nov 2026); Gatekeeper v3.23.1 (2026-08-27, year inferred) evaluates VAP-style CEL via the K8sNativeValidation engine and generates VAP/VAPB from templates/constraints (beta since 3.20, on by default); Kubewarden's cel-policy Wasm module takes settings that are literal VAP spec fragments, and `kwctl scaffold vap` converts native VAPs. Rego (Gatekeeper legacy, Conftest, Trivy) persists but is no longer where new policy is written. Practical common denominator for a rewrite: "CEL over an admission-shaped request".

Dominant shift-left practice is a CLI evaluating a directory of policy manifests against a directory of resource manifests in CI. Most complete offline evaluators: `kyverno apply`/`kyverno test` and `gator test`/`gator verify`. Kyverno emulates the cluster through side files: Values (`cli.kyverno.io/v1alpha1` kind Values: globalValues, policies[].rules[].values, policies[].resources[].values, namespaceSelector[]{name,labels}, subresources), UserInfo (`--userinfo`: clusterRoles, roles, userInfo.username/groups), Context (`--context-file`, kind Context, spec.resources full objects for resource.Get()/List plus image metadata), and `--parameter-resource` for paramKind objects; kyverno-test.yaml adds globalContextEntries.resourceFiles and per-result flags isValidatingAdmissionPolicy/isValidatingPolicy/isMutatingAdmissionPolicy plus patchedResources/generatedResource. gator verify uses a Suite (`test.gatekeeper.sh/v1alpha1`) with cases carrying object, inventory (injected into data.inventory), and AdmissionReview wrappers for operation/UserInfo; `gator sync test` checks SyncSet/Config coverage of the `metadata.gatekeeper.sh/requires-sync-data` annotation against a GVKManifest. Kubewarden's `kwctl run` evaluates a Wasm policy against a recorded AdmissionReview JSON and can `--record-host-capabilities-interactions FILE` on a live run and later `--replay-host-capabilities-interactions FILE` — the cleanest "snapshot the cluster's answers" mechanism found, but per-request, not a cluster model.

Nobody ships a first-class "export this cluster's admission posture as a portable snapshot and evaluate against it"; it is hand-assembled via `kubectl get vap,vapb,map,mapb,clusterpolicy,vpol,constrainttemplates,constraints,clusteradmissionpolicies -o yaml` plus Namespace objects, param resources, and OpenAPI/CRD schemas (kubectl-validate `--local-schemas/--local-crds` layout, or kubeconform + yannh/kubernetes-json-schema + datreeio/CRDs-catalog). Emulation is partial everywhere: request.userInfo must be supplied; `authorizer.*` CEL needs RBAC, which no offline tool models (Kyverno playground swaps in a dry-run client); referential data must be provided as inventory/Context files; MAP has no dry-run/validationActions by design; PSA is a separate code path (`k8s.io/pod-security-admission`, namespace labels `pod-security.kubernetes.io/{enforce,audit,warn}[-version]`, plus apiserver AdmissionConfiguration exemptions invisible from kubectl). Go embeddability is good where it matters: `k8s.io/apiserver` v0.37.0 (2026-08-26) exposes `pkg/admission/plugin/policy/validating` (Validator/NewValidator, PolicyDecision, TypeChecker) and `policy/mutating`; Kyverno is importable (go.mod Go 1.26.6, k8s.io/apiserver v0.36.4, cel-go v0.31.0, one replace: fork of k8s.io/pod-security-admission; very heavy tree); kyverno/playground backend (pseudo-version 2026-09-02) shows the embedding shape (`NewProcessor(params, cluster.Cluster, kyverno ConfigMap, dclient.Interface, ConfigmapResolver, PolicyExceptionSelector, TypeConverterManager, RESTMapper)` then `Run(ctx, policies, resources, oldResources)`); Gatekeeper's engine is `open-policy-agent/frameworks/constraint/pkg/client` (pseudo-version 2026-09-08: `NewClient(Driver(rego|k8scel), Targets, EnforcementPoints)` + AddTemplate/AddConstraint/AddData/Review → *types.Responses); OPA v1.20.2 (2026-09-03) is a plain Go library (`github.com/open-policy-agent/opa/v1/rego`). Kubewarden's evaluator is Rust/Wasm — shell out. Direction: policies converge on VAP/MAP CEL, distribution moves to OCI (gator `--image`, kwctl `registry://`, Trivy bundles, Conftest push/pull), and 1.37 static-manifest admission makes "policies as files on disk" official — the shape a pseudo-cluster snapshot should take.

## Pain-point evidence

- **No portable admission-posture snapshot**: Kyverno needs Values/UserInfo/Context/--parameter-resource; gator needs inventory + GVKManifest + AdmissionReview wrappers; kwctl needs recorded AdmissionReview + record/replay file — none generated from a cluster (release-1-12-0.kyverno.io apply usage; gatekeeper gator docs; kwctl cli-docs via Context7).
- **Undiscoverable admission context** (request.userInfo, authorizer, RBAC, PSA apiserver defaults/exemptions) makes offline results diverge from real denies (k8s VAP docs; PSA docs; pkg.go.dev kyverno/playground/backend/pkg/engine).
- **Mutation precedes validation but tools validate pre-mutation objects; MAP has no dry-run**: KEP-3962 "No validationActions field (unless anyone can think of any useful way to offer a dry-run type option)"; Kyverno tests need explicit patchedResources (KEP-3962 README; Kyverno CLI docs via Context7).
- **Referential policies fail or silently pass offline** unless objects supplied; gator objects need metadata.namespace; K8sNativeValidation cannot use referential data (gator docs; Gatekeeper VAP docs).
- **Engine churn**: ClusterPolicy "officially deprecated — final release with full support" in 1.19, removed 1.20; kwctl archived 2026-01-19, cel-policy 2026-01-20 (Kyverno 1.19 blog; kubewarden/kwctl; kubewarden/cel-policy).
- **Linters encode vendor opinions, not the cluster's policy**: kube-score no custom checks; kube-linter/Polaris checks are user-authored, not imported (repos).
- **Offline schemas lag installed CRDs**: kubeconform relies on yannh/kubernetes-json-schema + datreeio/CRDs-catalog or manual openapi2jsonschema; kubectl-validate needs --local-crds or a live context (repos).
- **SaaS-backed validators die**: Datree closed 2023-07, archived 2024-06-06; jsPolicy silent since 2024-06.

## Design implications

1. Define a versioned on-disk cluster-snapshot bundle (OCI artifact or directory): (a) OpenAPI v3 per group/version in kubectl-validate layout + CRDs; (b) API discovery/GVK list (GVKManifest idea) to flag unsupported kinds; (c) policies: VAP/VAPB/MAP/MAPB in 1.37 static-manifest form, Kyverno ClusterPolicy + CEL types + PolicyException, Gatekeeper ConstraintTemplates + Constraints (+Config/SyncSet), Kubewarden (Cluster)AdmissionPolicy(+Group); (d) paramKind/paramRef objects; (e) all Namespace objects (namespaceSelector, namespaceObject, PSA labels); (f) allowlisted referential inventory (ResourceQuota, LimitRange, Ingress, NetworkPolicy, existing workloads); (g) optional operator-supplied "unobservable" section: PSA AdmissionConfiguration defaults/exemptions, apiserver admission plugins, RBAC subset for the CI identity, engine versions.
2. Importer = single `snapshot` command using client-go discovery + dynamic client with read-only RBAC; record engine chart versions since semantics differ across versions (Kyverno 1.19→1.20).
3. Evaluation engine: embed k8s.io/apiserver policy/validating + policy/mutating for exact VAP/MAP parity (TypeChecker at edit time, PolicyDecision for results); k8s.io/pod-security-admission for PSA; frameworks constraint client (rego + k8scel drivers, AddData with inventory) for Gatekeeper; Kyverno pkg/engine via playground-style Processor or shell out to `kyverno apply` with generated side files; shell out to `kwctl run` with generated AdmissionReview and replay file. Pin k8s.io/* per snapshot minor if feasible, else warn on skew.
4. Simulate real admission order: schema/structural → mutation (MAP, Kyverno MutatingPolicy, Gatekeeper Assign*) → validation (VAP, Kyverno, Gatekeeper, Kubewarden, PSA on pod template). Show mutated-object diff; validate post-mutation object.
5. Severity mapping: Deny/Fail → Blocking; VAP Warn / Kyverno Audit / Gatekeeper warn+dryrun / PSA audit+warn → Warning; pass-with-audit-annotations → Info. Preserve messageExpression output verbatim; cite source policy name/kind.
6. Model admission context explicitly in the workspace: pipeline/controller identity (username, groups, UID, extra) → request.userInfo; operation (CREATE vs UPDATE with oldObject from snapshot live object); target namespace. Argo CD/Flux service accounts as first-class setting.
7. Treat unobservable inputs as declared assumptions with UI badges ("PSA exemptions unknown", "authorizer() evaluated as allow"), never silent passes; `--strict` mode turns unknowns into Warnings.
8. Edit-time: CEL type-check + JSON-schema per keystroke (cheap); full admission simulation on save/preview; CI outputs matching conventions (Kyverno PolicyReport/ClusterReport, SARIF, JUnit).
9. Plugin depth: plugins for (1) per-engine/vendor snapshot importers (OpenShift, EKS Pod Identity), (2) external lookups needing record/replay (registry, DNS, HTTP — mirror kwctl), (3) renderers (Helm/Kustomize/Compose). Do NOT make policy engines gRPC plugins — they are Go libs/CLIs needing in-process performance and shared type environments; a CLI shell-out adapter (kyverno, gator, kwctl, kubeconform) covers the long tail.
10. Rule authoring in UI: JSON Schema checks (Polaris), template+params (kube-linter), raw CEL with VAP variable set; store user rules as VAP/ValidatingPolicy manifests for later promotion to cluster.
11. Always render Helm/Kustomize/Compose to final manifests before evaluation and back-map violations (JSONPath in rendered object → template/values key) for inline UI errors — the whitespace no surveyed tool fills.
12. Distribute snapshots and rule packs as signed OCI artifacts; zhi's cosign/OCI marketplace pipeline is reusable.
13. Docker Compose has no admission layer: reuse the engine with Kyverno ValidatingPolicy JSON mode / Rego / JSON Schema over the compose doc; "snapshot" = host facts (Docker/Compose versions, networks/volumes, port conflicts) from a small importer.

## Uncertainties

- Gatekeeper v3.23.1, Checkov 3.3.17, kubeconform v0.8.0 dates: year inferred 2026 (GitHub omitted year); verify with `gh release view`.
- kwctl: one fetch showed "v1.31.0 Nov 24, 2026" (impossible; correct 2025-11-24); confirm kwctl binary ships with adm-controller tags (v1.37.2).
- kubectl-validate: CEL x-kubernetes-validations/defaulting execution unconfirmed; built-in schemas past 1.35 unconfirmed.
- Kyverno CLI `--context-file` vs older `--context-path`, and Context spec.images shape — check `kyverno apply --help` on v1.19.1.
- Trivy flag naming (--namespaces vs --check-namespaces; --config-check vs --config-policy) — verify against v0.74.0.
- Playground support for VAP/MAP/all CEL types asserted by 1.19 blog, not by repo README.
- Kubewarden and Kyverno CNCF status not re-verified.
- Whether Gatekeeper's k8scel driver exposes request.userInfo/namespaceObject offline (docs 404'd).
- PSA apiserver defaults/exemptions non-discoverable — human decision on unknowns (assume none? block?).
- Version skew: embedding k8s.io/apiserver v0.37 vs clusters on 1.34–1.36 may differ in CEL libs/cost; decide multi-version support (per-minor evaluators vs latest-only + warning).
- Kyverno's go.mod replace of k8s.io/pod-security-admission with a fork may conflict with importing upstream in the same binary — needs a spike (licensing Apache-2.0 is fine).
