# cluster-state-import

**Dimension:** importing/snapshotting a cluster's constraints so manifests can be validated offline against a "pseudo cluster".

## State of the slice in 2026

Kubernetes 1.37 (2026-08-26) is current; 1.35/1.36 supported. Everything that constrains a deploy falls into five layers of decreasing offline-emulability. **L1 API surface + schemas:** aggregated discovery (`/api`, `/apis` with `Accept: application/json;v=v2;g=apidiscovery.k8s.io;as=APIGroupDiscoveryList`, stable since 1.30); OpenAPI v3 (`/openapi/v3` index -> `/openapi/v3/apis/<group>/<version>?hash=...`, stable 1.27, lossless: keeps default/nullable/oneOf/x-kubernetes-*; v2 is lossy); raw CRDs (`apiextensions.k8s.io/v1`, structural `openAPIV3Schema`, `default`, pruning, `x-kubernetes-validations` CEL incl. transition rules `oldSelf`/`optionalOldSelf`, `messageExpression`, `fieldPath`, ~100k estimated-cost per CRD plus per-request runtime budget, CRDValidationRatcheting). Since 1.36 (DeclarativeValidationForNative GA, KEP-5073) native-type validation is tag-driven and, per the release blog, published as `x-kubernetes-validations` in OpenAPI — closing much of the historical "OpenAPI is a best-effort replication of handwritten apiserver validation" gap. **L2 built-in admission plugins** (1.37 defaults: CertificateApproval/Signing/SubjectRestriction, DefaultIngressClass, DefaultStorageClass, DefaultTolerationSeconds, LimitRanger, MutatingAdmissionPolicy, MutatingAdmissionWebhook, NamespaceLifecycle, PersistentVolumeClaimResize, PodSecurity, Priority, ResourceQuota, RuntimeClass, ServiceAccount, StorageObjectInUseProtection, TaintNodesByCondition, ValidatingAdmissionPolicy, ValidatingAdmissionWebhook) are deterministic and data-driven, emulable given ResourceQuota (spec.hard + status.used, scopeSelector), LimitRange (min/max/default/defaultRequest/maxLimitRequestRatio; LimitRanger MUTATES defaults before validating), namespace `pod-security.kubernetes.io/{enforce,audit,warn}[-version]` labels plus apiserver AdmissionConfiguration exemptions (usernames/runtimeClasses/namespaces — NOT visible via API), StorageClass/IngressClass default annotations (`storageclass.kubernetes.io/is-default-class`, `ingressclass.kubernetes.io/is-default-class`), PriorityClass/RuntimeClass existence, NamespaceLifecycle (exists, not Terminating). **L3 CEL policies:** ValidatingAdmissionPolicy (+Binding; GA 1.30, `admissionregistration.k8s.io/v1`; validationActions Deny/Warn/Audit; variables object/oldObject/request/params/namespaceObject/authorizer; paramRef -> ConfigMap/CRD) and MutatingAdmissionPolicy (GA 1.36, v1; patchType ApplyConfiguration|JSONPatch; reinvocationPolicy) — pure functions except `authorizer.*` (needs RBAC), all snapshot-able. New in 1.36 alpha: manifest-based/static policies loaded from a control-plane directory, names ending `.static.k8s.io`, immutable via API — API snapshots may miss them (unverified). Third-party engines (Kyverno ClusterPolicy + ValidatingPolicy/MutatingPolicy/GeneratingPolicy/DeletingPolicy in `policies.kyverno.io/v1` as of 1.19.0 2026-08-20; Gatekeeper ConstraintTemplate/Constraint with Rego or K8sNativeValidation CEL, auto-generating VAP/VAPB since v3.17; Kubewarden ClusterAdmissionPolicy Wasm) are API objects with offline CLIs (kyverno, gator, kwctl) — only for their pure parts. **L4 webhooks:** configs (rules, namespaceSelector, objectSelector, matchConditions CEL, failurePolicy, sideEffects, reinvocationPolicy) are snapshot-able and predict WHICH request hits WHOM; logic is opaque. **L5 authorization + live state:** RBAC (SelfSubjectAccessReview/SelfSubjectRulesReview/`kubectl auth can-i --list --as=...`; rules snapshot-able and evaluable offline; webhook/ABAC authorizers not), existing resources (ownership, SSA managedFields conflicts, immutable fields like Deployment selector/Service clusterIP/PVC storageClass, name collisions), node labels/taints/capacity, `ResourceQuota.status.used` (moving target), opaque-webhook mutations.

**Dominant practice** is a layered pipeline: (1) CI schema validation with kubeconform or kubectl-validate; (2) policy unit tests with `kyverno apply/test`, `gator verify/test`, `kwctl run`; (3) deprecation checks with pluto (kube-no-trouble dormant; nova off-topic); (4) the only high-fidelity check — `kubectl apply --dry-run=server --validate=strict` / `kubectl diff --server-side` / `helm install --dry-run=server` (Helm 4.3.0) / `flux diff kustomization` (Flux 2.9) / Argo CD Server-Side Diff (stable since 3.1). Server dry-run runs the full chain (schema, defaulting, quota without consuming, LimitRanger, PodSecurity, VAP/MAP, webhooks with sideEffects None|NoneOnDryRun; others fail with "does not support dry run"), needs RBAC for the real verb, and cannot see controllers (a Deployment passes while its Pods are rejected by PodSecurity enforce or quota).

**Where it is heading:** policy consolidates on CEL inside the apiserver (VAP GA 1.30, MAP GA 1.36, declarative native validation GA 1.36 into OpenAPI; Gatekeeper/Kyverno emit/consume VAP; Kubewarden converts VAP) — so a growing share of constraints is pure data + CEL, executable offline with cel-go plus `k8s.io/apiserver/pkg/admission/plugin/cel` and the apiextensions CRD CEL validator. Webhooks remain the irreducible black box (bex.co 2026-09-07: delete webhooks whose logic is static; keep those needing external state). Nobody ships a "pseudo cluster" as a file format; closest substrates are kwokctl snapshot export/restore and envtest. Net snapshot = {discovery + OpenAPI v3 per group-version (hash-addressed) + CRDs + VAP/VAPB/MAP/MAPB + params + webhook configs (metadata) + Namespaces (labels) + ResourceQuota (spec+status) + LimitRange + StorageClass/IngressClass/GatewayClass/PriorityClass/RuntimeClass + RBAC + engine policy CRs + optional Nodes + optional existing workloads}. Offline fidelity: high for L1-L3 and RBAC, medium for quota (stale status.used), zero for webhook logic; live server dry-run stays the last gate.

## Pain-point evidence

- Offline OpenAPI validation diverged from live behaviour (nullable arrays, enums); kubernetes/kubernetes#95407 rotted unfixed; kubectl-validate README: OpenAPI is "best-effort replication of the handwritten validation rules".
- kubeconform README: server-side validations "not part of the OpenAPI specifications ... use a 3rd-party tool or kubectl --dry-run=server".
- CRD catalogs go stale and break pipelines (steadforce/crds-catalog exists for "automated updates to avoid failing build pipelines"); extraction is bash+python producing lossy JSON Schema; Datree defunct.
- Server dry-run fails/lies with side-effect webhooks, can't see controllers or referenced objects (API concepts docs; prometheus-operator#3704; OneUptime 2026-02-09).
- Workload passes, Pods fail: PSA enforce "applied only to resulting pod objects"; quota docs: "Creating a Deployment that exceeds quota succeeds, but Pods within it will fail".
- Policy CLIs need hand-written mocks; referential/external-data policies undecidable offline (Kyverno mocks only in 1.19; gator docs; kwctl record/replay).
- Identifying the blocking webhook is its own debugging exercise (OneUptime 2026-09-04).
- Policy invisible to API: AdmissionConfiguration PSA exemptions; 1.36 `.static.k8s.io` policies (blog 2026-05-04).
- kube-no-trouble drift (rules to 1.32); pluto keeps pace.
- GitOps previews only post-PR with live cluster; Argo SSD skips new resources and excludes mutation webhooks by default; flux diff needs Flux CRDs.

## Design implications

1. Versioned ClusterSnapshot format (OCI artifact or directory, YAML/JSON) with provenance (cluster, context, server version, timestamp, identity) and layers: discovery (APIGroupDiscoveryList JSON); openapi/v3 in kubectl-validate layout keyed by `?hash=` for incremental re-import; crds/ raw CRDs (derive JSON Schema only on export); admission/ (VAP/VAPB, MAP/MAPB, paramRef objects, webhook config metadata); namespaces/ (Namespace labels, ResourceQuota spec+status, LimitRange); cluster catalogs (StorageClass, IngressClass, GatewayClass, PriorityClass, RuntimeClass); rbac/ (+ SelfSubjectRulesReview for deploying identity); engines/ (Kyverno, Gatekeeper incl. SyncSets/Config, Kubewarden); optional Nodes and existing workloads; manual overlay for PSA exemptions, static policies, webhook stubs — marked "declared, not observed".
2. Importer is a kubectl-free Go client over discovery + OpenAPI v3 + fixed kind list; works read-only, degrades gracefully recording forbidden layers ("quota unknown: no list on resourcequotas"); `--filter` by workspace namespaces; hash/resourceVersion per layer.
3. Offline validation = ordered apiserver-chain emulation per object: discovery presence (replaces pluto/kubent) -> strict fields + structural schema + defaulting + CRD CEL via customresource.Strategy (kubectl-validate composite: snapshot -> builtins for server version -> live) -> NamespaceLifecycle -> LimitRanger (reimplement, mutate then validate) -> PodSecurity via pod-security-admission with labels + overlay exemptions -> ResourceQuota via `CheckRequest` with status.used baseline flagged stale -> MAP then VAP via plugin/cel with authorizer backed by snapshot RBAC -> engine adapters -> webhook match prediction. Severity map: schema/CEL/Deny -> Blocking; Warn/Audit, PSA warn/audit, webhook predictions, stale quota -> Warning; discovery/deprecation -> Info or Blocking by removed-in.
4. Expand workloads (Deployment/StatefulSet/DaemonSet/Job/CronJob/ReplicaSet) to Pods before emulation (like gator expand / Kyverno autogen).
5. Three fidelity tiers, one interface: A pure-Go in-process (ms, live UI); B envtest/kwokctl hydrated from snapshot (webhooks rewritten to Ignore or local stub); C live `--dry-run=server` + `auth can-i`. Tag every finding with its tier.
6. Webhooks as first-class unknowns: compute match (rules x namespaceSelector x objectSelector x matchConditions), let engine adapters claim known services (kyverno-svc, gatekeeper-webhook-service, policy-server-*, cert-manager-webhook); never present results as complete when unclaimed webhooks match.
7. Expose decidability like `gator sync test`: per policy list needed referential data (Kyverno apiCall/resource.Get, Gatekeeper inventory GVKs, VAP paramRef/namespaceObject/authorizer) and whether the snapshot has it; prompt to fetch.
8. Emit interoperable artifacts: kubeconform schema dir, kubectl-validate `--local-schemas` dir, Kyverno context/values file, gator inventory; accept AdmissionReview JSON input.
9. Narrow plugin surface: importers are core Go over the dynamic client; the single extension point is "policy engine adapter" (snapshot dir + candidate objects -> findings), as subprocess or Wasm; apiserver emulation is core.
10. Freshness and target-version: store server version; allow "target version" what-if (swap builtins + discovery, keep CRDs); warn on age > N days or stale quota; hash-addressed OpenAPI keeps refresh cheap.
11. Consume server-published `x-kubernetes-validations` for built-ins (1.36+) instead of hardcoding; verify per version.
