# environments-secrets-drift

**Dimension:** multi-environment value management, secrets, promotion and drift in GitOps (Kubernetes + Compose), state of 2026-09. Dates/stars from GitHub API on 2026-09-12 unless marked uncertain.

## State of the slice in 2026

Multi-env values are still layered by three unchanged mechanisms: (1) Helm values-file stacking (`-f base.yaml -f values-prod.yaml --set/--set-string/--set-file/--set-json`; last file wins; `null` deletes a key; `values.schema.json` JSON Schema draft-07 validated against the FINAL merged `.Values` incl. all subchart schemas at install/upgrade/lint/template; `--skip-schema-validation` bypasses). Helm 4.3.0 is current (2026-09-09); Helm 3 (v3.22.0) gets security fixes only until 2026-11-11. (2) Kustomize overlays (v5.8.1, 2026-02-09) plus `kind: Component` (`kustomize.config.k8s.io/v1alpha1`, since v3.7.0) for opt-in feature composition; no values, no validation of output. (3) A GitOps-controller substitution layer: Flux `Kustomization.spec.postBuild.substitute/substituteFrom` (envsubst `${VAR}`/`${VAR:=default}`/`${var/sub/repl}` from cluster-side ConfigMaps/Secrets; since kustomize-controller 1.9.0 / Flux 2.9 (~June 2026, inferred) the `StrictPostBuildSubstitutions` gate is on by default so a missing var without default FAILS reconciliation; replayable with `kustomize build ./apps | flux envsubst --strict`), and Argo CD ApplicationSet generators (git file generator flattens per-env `config.json`/YAML into `{{.values.x}}`; cluster generator exposes labels/annotations on cluster Secrets; matrix combines exactly two generators, one nesting level; `goTemplateOptions: ['missingkey=error']`; Progressive Syncs beta since 3.3.0). Typed alternatives: Timoni (CUE, v0.34.0 2026-08-30, bundles still v1alpha1, single maintainer) and Holos (CUE rendered-manifests, last release v0.106.0 2025-11-24, 167 stars, slowing). Helmfile 1.7.4 remains the pragmatic `environments: + values + SOPS secrets` tool with precedence env defaults < YAML/gotmpl < HCL < encrypted secrets < CLI. Flux guidance: trunk-based monorepo `apps/{base,staging,production}` + `clusters/<name>`, no long-lived env branches.

Promotion consensus in the Argo ecosystem is the rendered-manifests / hydrated-branch pattern: Argo CD Source Hydrator (beta since 3.5.0, ~Aug 2026; `spec.sourceHydrator.{drySource,syncSource,hydrateTo}`; commits `manifest.yaml` + `hydrator.metadata` git note with dry SHA/author; determinism required, secret injection during hydration forbidden; Argo will NOT move `hydrateTo` -> `syncSource`, "you need your own tooling") into `environment/<env>-next` branches; argoproj-labs/gitops-promoter (v0.38.1 2026-09-10, 756 stars, self-labelled experimental) opens/merges PRs `-next -> environment/<env>` when CommitStatus gates pass (ArgoCDCommitStatus, DependentsSuccessfulCommitStatus, TimedCommitStatus, ScheduledCommitStatus, GitCommitStatus, WebRequestCommitStatus; ordering NOT automatic). Kargo (Akuity, v1.11.4 2026-09-03, 3.65k stars; Warehouse/Freight/Stage/Promotion, ~70 expr-lang steps incl. yaml-update, helm-update-image, kustomize-set-image, git-open-pr, argocd-update; tf-plan/apply, ServiceNow, custom container steps Enterprise-only) is the commercial promotion orchestrator. Image bumps: Flux image automation (`image.toolkit.fluxcd.io/v1`, marker `# {"$imagepolicy": "ns:name:tag"}` in any YAML incl. Helm values), Argo CD Image Updater (v1.3.0 2026-08-13, write-back to `.argocd-source-<app>.yaml` or Helm values), Renovate (44.82.3; helm-values, flux, argocd (no default patterns), kustomize, helmfile, docker-compose managers), Dependabot (helm Chart.yaml, docker, docker-compose only; no Kustomize/Flux/Argo/values.yaml).

Secrets: Argo CD docs "strongly recommend" operator-based secrets and "strongly caution against" generation-style plugins (rendered secrets in repo-server/Redis); argocd-vault-plugin is dormant (v1.18.1 2024-06-07, last push 2024-12-18). ESO (v2.10.0 2026-08-28, 6.85k stars, stable `external-secrets.io/v1`, 40+ providers, OpenBao dedicated provider since 2.7.0, PushSecret, generators, `target.template`) is the reference-in-Git model. SOPS (v3.13.3 2026-07-23; age/KMS/Vault-OpenBao transit/PGP; `.sops.yaml` creation_rules with `encrypted_regex`; `exec-env`, `--output-type dotenv`; Flux-native decryption with workload identity since 1.9.0) and Sealed Secrets (v0.40.0 2026-09-10; repo moved bitnami-labs -> bitnami 2026-06-15 with Helm repo URL change; /v1/rotate and /v1/verify decryption-oracle fixes in 0.39.0/0.40.0; ciphertext per cluster cert) are the encrypted-in-Git models. Vendor operators (VSO v1.5.1, Infisical, Doppler v1.7.1 Oct 2025, Bitwarden beta `--devel`, 1Password v1.12.0) all converge on CRD-with-remote-path -> operator -> Secret -> annotation-driven restart. Drift is now built into reconcilers: Argo CD Server-Side Diff (stable 3.1.0; `argocd.argoproj.io/compare-options: ServerSideDiff=true`, `IncludeMutationWebhook=true`; validating webhooks run at diff time), `selfHeal` (~5s; otherwise 120s +/- 60s), `ignoreDifferences` (jsonPointers/jqPathExpressions/managedFieldsManagers) + `RespectIgnoreDifferences=true`; Flux HelmRelease `spec.driftDetection.mode: enabled|warn|disabled` with JSON-pointer `ignore`, kustomize-controller `spec.ignore` (1.9.0). All local diff tools (`kubectl diff --server-side`, `flux diff kustomization`, `argocd app diff --local --server-side-generate --exit-code`, helm-diff v3.15.13) need a live cluster. driftctl is in maintenance mode (v0.40.0 Dec 2023, never Kubernetes). Docker Compose has no promotion, drift, or reference-based secrets story at all; this is the whitespace.

## Pain-point evidence

- Values validated only after merge inside the controller (Flux HelmRelease NotReady, Argo Degraded); kustomize-controller CHANGELOG 1.9.0: reconciliation fails on missing var; Argo SSD docs: webhooks catch invalid resources "during the diff stage rather than sync stage" (still post-push).
- Every "valid for THIS cluster" check needs a live API server; kubectl diff docs "Requires live cluster"; kubeconform README "does not evaluate CEL rules"; argocd-diff-preview needs kind 60-90s.
- Matrix explosion: overlay explosion (secondary source devopsboys.com), matrix generator "Maximum two child generators", "Single nesting level"; Sealed Secrets cert per cluster.
- Env inputs live in-cluster (Flux substituteFrom; Argo cluster-Secret labels) so Git alone cannot reproduce output.
- Secret refs unverifiable at review (ESO remoteRef typos, Bitwarden UUIDs, AVP placeholders); Argo docs: plugin-rendered secrets visible to anyone with Redis/repo-server access.
- Promotion bolted on: hydrator "will not create a PR... use your own tooling"; gitops-promoter "ordering is not injected automatically"; Kargo v1.9 blog: key steps "exclusive to Akuity Kargo Enterprise".
- Fragmented audit: Argo security doc: Git history "does not necessarily correlate one-to-one" with cluster events; only `hydrator.metadata` bridges dry SHA/author.
- Machine edits break comments/markers: Image Updater 1.3.0 changelog "Preserved YAML formatting in Helm values files" (was a bug).
- Secrets-tooling churn: AVP dormant, Sealed Secrets move (#1982, old Helm URL 404) + oracle CVEs, Vault BUSL/IBM -> OpenBao, Doppler stale.
- Compose: zero equivalents; `.env` copied by hand; only Dependabot bumps and SOPS/Infisical/Doppler CLIs.

## Design implications

1. Pseudo-cluster snapshot must contain: server version + served API versions (`kubectl api-versions`, `/openapi/v3`); all CRDs with OpenAPI v3 incl. `x-kubernetes-validations`; VAP + bindings, Kyverno ClusterPolicy/Policy/ValidatingPolicy/PolicyExceptions; namespaces with labels, ResourceQuota, LimitRange; webhook configurations (flagged "cannot evaluate offline"); GitOps inputs (Flux substituteFrom ConfigMaps/Secrets redacted-but-keyed, Argo cluster-Secret labels/annotations, (Cluster)SecretStore names+providers, Sealed Secrets cert); installed Helm releases/Applications/Kustomizations/HelmReleases. Store as signed, versioned tarball/OCI artifact keyed by cluster + capture time ("valid against prod@2026-09-12T10:00").
2. Reuse evaluators: OpenAPI + CEL via `k8s.io/apiextensions-apiserver` libraries (Timoni proves feasibility in Go); Kyverno CLI for VAP/ValidatingPolicy; conftest for Rego; render with real Helm 4 SDK / Kustomize kyaml so output equals controller output.
3. Validation = f(value tree, environment, snapshot) -> per-env result. UI: env x (component/value) matrix, cells valid/warning/blocking plus "unknown" (cluster-only checks) and "stale" (old snapshot). Keep Info/Warning/Blocking; add `scope` (env/cluster/global) and `provenance` (value paths -> rendered field; requires value->template->field lineage).
4. Layering model: base < env < cluster < runtime(substituteFrom) < machine-managed(image tags), with `${VAR:=default}` strictness and `null` deletion; show effective value per env with source layer.
5. Secrets as typed references `ref://<store>/<path>#<key>[@version]`, never values. Render: ExternalSecret (ESO v1) default, SealedSecret (snapshot cert), SOPS file (per `.sops.yaml`), VaultStaticSecret/InfisicalSecret optional; Compose resolves at export (`sops exec-env`, provider CLI). Blocking if store missing in snapshot; Warning if key missing at provider (needs read access). Import AVP `<path:...#key>`.
6. Fit into promotion, do not own it: emit PRs/commits to the DRY repo; CI mode `zhi validate --env prod --snapshot prod.tgz --exit-code` posting commit statuses; act as gitops-promoter CommitStatus provider or Kargo container step. Never require an in-cluster controller.
7. Comment/format-preserving YAML editing mandatory (yaml.v3 Node / kyaml); machine-managed fields read-only in UI.
8. Drift/audit is read-only integration: query Argo CD (sync, SSD diff, Events with actor) and Flux (conditions, drift Events); correlate hydrated SHA <-> dry SHA (git note) <-> value change <-> author.
9. Plugin depth: out-of-process plugins only where heterogeneity exists: secret stores, snapshot importers (k8s, Compose host, cloud policies), render targets (Helm values / Kustomize patch / Flux ConfigMap / Compose .env). Validators as data (schema, CEL, Rego, Kyverno files) cover ~90% with zero plugin process. UI plugin type unnecessary if core exposes HTTP/MCP API.
10. Snapshot trust like a lockfile: cluster identity, capture time, user, hash; refuse Blocking-clear on stale snapshots; "online mode" upgrades to `kubectl --dry-run=server`/Argo SSD when kubeconfig present.
11. Environment metadata first-class: name, ordered promotion position, target clusters (1:N), namespaces, GitOps tool + branch/path/Application/Kustomization, secret store bindings, matrix dimensions (region, tenant); derive from ApplicationSet generators / Flux dirs / Kargo Stages on import.
