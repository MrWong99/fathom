# plugin-architectures

## State of the slice (2026)

Every mature DevOps tool has converged on one of four extension shapes, and the choice tracks trust and lifecycle, not fashion. (1) **Out-of-process gRPC subprocess** via hashicorp/go-plugin v1.8.0 (2026-04-29): Terraform/OpenTofu providers (tfplugin6 protocol 6.11, 36 RPCs, DynamicValue msgpack|json), Vault plugins (now also OCI images under runc/gVisor, Linux-only), Grafana backend plugins, Pulumi providers (~20 RPCs, `pulumi-resource-<name>`), Crossplane composition functions (`apiextensions.fn.proto.v1 FunctionRunnerService.RunFunction`, one Deployment per Function, mTLS). Wins where a plugin owns a long-lived, credentialed integration and the host is a single vendor binary. (2) **WASM sandbox**: Kubewarden (waPC + WASI, OCI + sigstore, `kwctl run` offline), Helm 4 (extism/v1 beside subprocess, HIP-0026), Envoy proxy-wasm (ABI v0.2.1, one-maintainer org; Envoy now invests in unsandboxed "dynamic modules" — a public regret of Wasm copy/ABI overhead), kpt `--allow-alpha-wasm` (never graduated). Wins for small, pure, untrusted transforms/policies; loses when the plugin needs network/FS/credentials, where hosts reinvent host-function APIs (Kubewarden `kw.k8s/kw.oci/kw.sigstore/kw.net`; Extism `allowed_hosts/allowed_paths`). (3) **In-process same-language modules**: Backstage (npm packages, "new backend system", experimental dynamic-plugins loader, sustained versioning pain), VS Code (separate extension-host process, finalized API never breaks, signed VSIX), Grafana frontend (JS sandbox public preview since 11.5, off by default, cannot sandbox Angular or Grafana-signed plugins). Maximizes DX and upgrade/breakage cost. (4) **Declarative/expression-only**: Kyverno moved from JMESPath ClusterPolicy (deprecated, removal v1.18–v1.20 by Oct 2026) to CEL ValidatingPolicy GA in 1.17 with ~14 fixed host libraries and no user-defined libraries; Kubewarden cel-policy is one Wasm module evaluating VAP-compatible CEL; Renovate has no code plugins (regex/JSONata custom managers, JSONata customDatasources, admin-allowlisted postUpgradeTasks); Flux controllers refuse Kustomize plugins and extend only via CRDs ("no user code executes"), while Flux 2.9 (2026-06-30) added a CLI-only plugin system (`flux plugin install schema@sha256:…`, `~/fluxcd/plugins`, catalog at github.com/fluxcd/plugins) whose first-party `schema` plugin validates manifests against JSON Schema + CEL — directly adjacent to zhi's proposed value.

Dominant GitOps-era practice: controllers/reconcilers are closed and declarative; extension happens at the CLI/CI edge (Flux plugins, krew, Helm cli/v1, Dagger modules) or via KRM-shaped contracts (ResourceList `config.kubernetes.io/v1` with `results[].severity error|warning|info`; Crossplane `SEVERITY_FATAL/WARNING/NORMAL`; Terraform Diagnostic ERROR/WARNING; LSP DiagnosticSeverity 1–4). Argo CD CMP v2 (sidecar + `argocd-cmp-server` over a Unix socket, `plugin.yaml` at `/home/argocd/cmp-server/config/plugin.yaml`, UID 999, `ARGOCD_EXEC_TIMEOUT` 90s, errors cached in Redis, one sidecar per plugin version) is universally described as painful (issue #15006 still open); its own proposal accepts "plugin.yaml format becomes a compatibility contract". Kustomize plugins never left alpha (`--enable-alpha-plugins` required; exec/Starlark/Go deprecated by KEP-2953; catalog KEP-2906 unimplemented; #5808 closed not-planned) — a 5-year signal that generic extension points in a config renderer do not graduate.

Direction: (a) gRPC subprocess stays default for trusted integrations and gained containerized isolation (Vault OCI, Crossplane pods) rather than moving to WASM; (b) WASM narrows to "pure policy/transform on bytes" with OCI + sigstore; Go hosts standardize on wazero v1.12.0 (2026-05-28, pure Go, no cgo), but the Extism Go SDK's last release is v1.7.1 (2025-03-02) while Extism core is at v1.30 (2026-06), and Helm 4.1/4.2/4.3 notes contain no further Wasm work — "Helm 4 Wasm plugins" is real but thin; (c) CEL is the lingua franca for K8s validation (VAP, Kyverno 1.17 GA, Kubewarden cel-policy, Flux schema plugin), and Terraform added provider-defined pure functions (protocol 6, TF 1.8+) — expressions with a host-curated library displace "write a plugin to validate"; (d) MCP (spec 2026-07-28) is a stateless HTTP/stdio request-response protocol with a registry (`server.json`; npm/pypi/oci/nuget/mcpb) — a viable agent-facing surface, not an internal boundary; (e) LSP 3.18 remains the model for an editor-agnostic diagnostics boundary (JSON-RPC over stdio, capability negotiation, pull diagnostics since 3.17, enum-tolerant versioning).

Net for the rewrite: zhi v1's four go-plugin types (config/transform/store/ui, OCI-signed, marketplace, mirror) are the Terraform/Vault shape — right for a platform, over-built for a validation tool whose users edit YAML. Nothing in 2026 rewards a pluggable UI (Grafana/Backstage are fighting sandbox/versioning debt) or pluggable transforms in the GitOps path (Flux forbids, Argo suffers, Kustomize never shipped). What is rewarded: fixed core + few first-party importers (cluster snapshot) and renderers (Helm values, Kustomize overlays, Compose, dotenv); validation as CEL/JSON Schema/OpenAPI with a curated library; optional WASM for third-party pure validators with OCI+sigstore; gRPC subprocess reserved for secret/credential resolvers and live-cluster importers.

## Pain-point evidence

- Argo #15006 (open): sidecar CMPs "difficult to initially set up"; "restart the sidecar to load a new plugin config"; docs: errors "cached by the repo-server in Redis. Restarting the repo-server Pod will not clear the cache." CMP v2 proposal accepts "plugin.yaml format becomes a compatibility contract", "Multiple sidecars needed for version support".
- Kustomize docs: "All Kustomize plugins are in alpha"; "do not run in any kind of kustomize-provided sandbox"; KEP-2953 deprecations; KEP-2906 no implementation; #5808 not-planned.
- Flux FAQ: "Due to security and performance reasons, Flux does not allow the execution of Kustomize plugins which shell-out to arbitrary binaries inside the kustomize-controller container."
- Helm migrate guide: getter/postrenderer Wasm tutorials "in progress"; 4.1.0 (2026-01-21)–4.3.0 no Wasm features; HIP-0026 still "draft"; Extism Go SDK v1.7.1 (2025-03-02).
- Envoy #35420: proxy-wasm org "only has one member", ABI spec dir "in-fact empty"; dynamic modules "fully trusted… same privilege level", "not hardened".
- Grafana sandbox: "Angular-based plugins are not supported", signed plugins unsandboxable; Backstage "new backend system", dynamic-feature-service "experimental", alpha/beta exports break on minor.
- Renovate #34567/#34175: JSONata manager loses replaceString because "we transform the original file content to json object".
- Kyverno: 14 libraries, no custom libraries; ClusterPolicy deprecated, removal v1.18–v1.20; Nirmata JMESPath→CEL migration guide (2026-07).
- Vault containerized plugins Linux-only, pre-pulled images, gVisor `--host-uds=create`; Crossplane render and kpt render require Docker.
- Pulumi: Python/TS providers "require their respective runtimes".
- MCP 2026-07-28 removed initialize/Mcp-Session-Id/GET stream; clients need era detection via 400 body inspection.

## Design implications

1. **Plugin depth matrix.** FIXED CORE: values tree with source positions (yaml.v3 nodes) and write-back; validation result type (KRM results[] + LSP range/code/codeAction); pseudo-cluster snapshot format + evaluator; Git integration; Web UI and LSP server. CONFIG-ONLY: source loaders (YAML/JSON/TOML/env/Helm values/Kustomize/Compose) by file patterns (Renovate shape); renderers as templates + output mappings; components as path groups; importer selection lists. SCRIPTED (CEL first, CUE/KCL second): all user validators with fixed host library (json/yaml, semver, cidr, duration, k8s quantity, image ref); imported VAP/Kyverno/Kubewarden CEL evaluated by the same engine untranslated. WASM (phase 2, optional): third-party checks CEL cannot express, OCI + sigstore, declared capabilities (allowedHosts/allowedPaths/memory/timeout), wazero with zhi-owned ABI (waPC or knqyf263/go-plugin). gRPC (keep, shrink to one interface): secret resolvers (Vault/SOPS/age/KMS) and live-cluster importers; first-party compiled in, external via checksum-pinned catalog. NOT PLUGGABLE: UI panels, GitOps-path transforms, store backends (Git is the store; drop store type).
2. Reduce four v1 types to at most two loadable kinds — `resolver` (gRPC) and `check` (WASM, bytes in → diagnostics out); everything else declarative or CEL. Thriving tools have one kind with a huge market or none.
3. Version like Terraform/Crossplane/LSP: proto package `zhi.plugin.v1`, additive RPCs gated by Server/ClientCapabilities bitfields, plugins request cluster schemas from host (required_schemas), tolerate unknown enums, manifest apiVersion + kind suffix (`check/v1`, `resolver/v1`).
4. Zero-network pre-cluster validation: snapshot bundles CRD OpenAPI v3 (`/openapi/v3`), VAP + bindings + params, Kyverno policies, Kubewarden policy settings, ResourceQuota/LimitRange, PodSecurity labels, Gatekeeper templates/constraints; reuse upstream engines as Go libraries (k8s.io/apiserver CEL admission, Kyverno CLI engine with `--context-file` semantics, kwctl-style AdmissionReview synthesis). Flux schema plugin owns generic schema checking; imported policy set is the whitespace.
5. Offline `zhi render --snapshot cluster.snap.tgz --values values.yaml` → manifests + diagnostics, as CI gate; controllers stay vanilla.
6. Expose validation via LSP (diagnostics, hover, code actions applying proposedValue) and MCP tools (stateless 2026-07-28 Streamable HTTP + stdio) — output surfaces, not plugin boundaries.
7. Distribution: OCI + cosign optional and lazy; first-party compiled in; WASM pulled by digest (`name@sha256:…`); gRPC resolvers via `-sha256` catalog plus allowlist for apply commands; lockfile with hashes (`.terraform.lock.hcl` model) for air-gap before a mirror server.
8. No marketplace/rating/search before third-party plugins exist; ship a curated krew-index-style file.
9. Preserve provenance/positions end-to-end: file:line:col for editors and PR annotations (code-quality/SARIF); UI edits round-trip comments and ordering.
10. Severity: keep Info/Warning/Blocking, map explicitly to KRM, LSP, Terraform, Crossplane, and K8s admission (VAP `Deny|Warn|Audit`) so a Warn-action VAP surfaces as Warning, not Blocking.
