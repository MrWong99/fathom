# k8s-config-languages

## State of the slice (Sept 2026)

Helm remains the gravitational centre. helm/helm has 30.2k stars; Helm v4.0.0 shipped 2025-11-12 (verified via official blog — a search snippet claiming April 2026 was wrong), v4.3.0 shipped 2026-09-09, and v3.22.0 (2026-09-10) is the final v3 feature release (v3 bug fixes ended 2026-07-08, security fixes end 2026-11-11). Helm 4's headline changes are in the deploy path — server-side apply (HIP-0023), kstatus-based `--wait` (HIP-0022), typed plugin system with Extism Wasm runtime (HIP-0026), multi-version chart packages (HIP-0020) — plus one quiet values-path change: values.schema.json is now validated by `github.com/santhosh-tekuri/jsonschema/v6` (drafts 4/6/7/2019-09/2020-12, `$ref` loaders for file/http(s)/urn), replacing Helm 3's draft-7-only gojsonschema. Kustomize is stable but slow (one 2026 release, v5.8.1 on 2026-02-09, mostly Helm-v4 compat); it has no values model at all and its KRM-function extension story has been `--enable-alpha-plugins`-gated for years. kpt reached v1.0.0 on 2026-08-31, re-legitimising the KRM Functions Specification (ResourceList in/out) as the lingua franca for client-side validate/mutate.

Dominant values practice is still untyped values.yaml merged into charts, with optional values.schema.json that many popular charts don't ship; two generators (losisin/helm-values-schema-json v2.6.0 2026-08-24, dadav/helm-schema 0.23.5 2026-08-24) synthesize schemas from `# @schema` comments, both defaulting to draft 2020-12. Pre-cluster validation is layered: `helm lint` (ERROR/WARNING, `--strict`, `--kube-version`, `--with-subcharts`), `helm template` (client-side; `--api-versions`/`--kube-version` fake Capabilities; `--disable-openapi-validation`), then `--dry-run=server` which needs a live API server. chart-testing (ct v3.14.0, 2025-10-08) is the CI convention: yamllint + yamale Chart.yaml schema + helm lint + install with `ci/*-values.yaml`. Nothing validates against cluster policies without a cluster.

The typed-language camp has matured but is niche: CUE v0.17.1 (2026-07-16, 6.3k stars, Go API now concurrency-safe, JSON Schema/OpenAPI round-trips); Timoni v0.34.0 (2026-08-30, 2.0k stars, seven releases Jul–Aug 2026, still "APIs may change", no controller); KCL (CNCF Sandbox since 2023-09-20, core repo last release v0.11.2 2025-04-18 while cli v0.12.10/kcl-go v0.12.5 shipped Aug 2026); Pkl 0.32.1 (2026-07-23, 11.5k stars, Go binding spawns the pkl CLI); Jsonnet/Tanka (v0.39.0 2026-08-27, untyped, cluster-only validation); cdk8s (near-daily automated releases, Node/jsii dependency, documented validation plugin Datree archived since 2024). Carvel ytt/kapp (Sandbox since 2022-09-14) are in maintenance but ytt's `--data-values-schema-inspect -o openapi-v3` remains the best example of a template tool exporting a UI-consumable schema. Holos is dormant (no release since v0.106.0, 2025-11-24; 167 stars). Nelm hit 1.0 in Jan 2026 (stable v1.26.2, 2026-07-22) with terraform-style `nelm release plan install`; werf 2.x (v2.78.x, 2026-09-09) has giterminism (`werf-giterminism.yaml`), the strongest "only committed config counts" stance. Direction: (1) rendered-manifests pattern is the GitOps-native shape; (2) schemas converge on JSON Schema for values and CRD openAPIV3Schema for resources, with CUE/KCL/Pkl bridging; (3) Helm 4 signals the plugin trend — few typed kinds, typed messages, Wasm sandbox with signing, subprocess as legacy; (4) SSA server dry-run is the only cluster-aware validation any tool has and always needs a live API server. **Nobody validates against an offline snapshot of cluster policies/quotas — whitespace for the zhi rewrite.**

## Pain-point evidence

- Helm 3 draft-7 ceiling (issue #13069); Helm 4's library switch broke charts with `$ref` to other schema files (issue #31260). — github.com/helm/helm/issues/13069, /31260
- helm.sh charts/registries/plugins pages carry "not yet been updated for Helm 4" (fetched 2026-09-12); plugin behaviour inferred from source. — helm.sh/docs/topics/plugins/
- Kustomize: "replacements cannot replace all uses of vars, as they target structured data whereas vars supports string replacement" (discussion #5046); v5.8.0 namespace-propagation regression fixed in v5.8.1.
- KRM functions alpha-gated for years; Flux/Argo default builds don't enable them. — functions-spec.md
- kubeconform README: "controllers still perform additional server-side validations that are not part of the OpenAPI specifications"; Tanka subset diff "only compares fields present in the local configuration". — github.com/yannh/kubeconform; tanka.dev/diff-strategy/
- Nelm's stricter SSA made users "fix long-standing issues in their Helm charts". — palark.com/blog/werf-v2-history-nelm-alternative-to-helm/
- Timoni under Flux: "app lifecycle management, bundling, runtime values injection and multi-cluster deployments are not available". — timoni.sh/gitops-flux
- API churn: Timoni 7 releases/8 weeks; CUE 0.17 removed deprecated Go API methods, changed modconfig.Registry; Pkl 0.32 changed name resolution and Java nullability. — respective release notes
- cdk8s docs still show `@datreeio/datree-cdk8s`; datree archived 2024-04-23. — cdk8s.io/docs/latest/cli/synth/
- KCL core no release since v0.11.2 while cli/kcl-go ship 0.12.x; Sandbox 3 years. — kcl-lang releases; cncf.io/projects/kcl/
- Go embedding awkward: pkl-go "spawning the pkl cli as a child process"; kcl-go "CGO is required when using plugins"; cdk8s Go needs jsii/Node. — pkl-lang.org/go/current/evaluation.html; kcl-go README

## Design implications

1. values.schema.json (draft 2020-12, draft-7 fallback) as primary form-schema input/output; validate with `github.com/santhosh-tekuri/jsonschema/v6`, replicating Helm's file/http(s)/urn `$ref` loaders and subchart-schema-on-merged-.Values so "valid in zhi" == "valid in helm install".
2. No schema shipped → synthesize: infer types from values.yaml defaults, parse `# @schema`/helm-docs comments (losisin/dadav convention), let user enrich in UI, write back values.schema.json to the chart repo.
3. CRD openAPIV3Schema from the imported cluster as second schema tier: convert to JSON Schema (kubeconform/openapi2jsonschema), validate rendered manifests offline; also import `x-kubernetes-validations` CEL rules so structural + CEL run without a cluster.
4. CUE (`cuelang.org/go` v0.17+, concurrency-safe) as internal unification engine: import values.schema.json + CRD schemas via encoding/jsonschema|openapi, unify with org policy CUE, export effective schema to JSON Schema for the UI. Hide CUE syntax from DevOps persona by default; expose as advanced policy layer.
5. Render via native tools: Helm through `helm.sh/helm/v4` (pkg/action DryRun client; pkg/chart v2, ready for charts v3 from internal/chart/v3); Kustomize via `sigs.k8s.io/kustomize/api/krusty` in-process; Timoni/KCL/Pkl/ytt via subprocess adapters. Keeps CGO_ENABLED=0; exclude kcl-go (CGO) and cdk8s (Node) from core.
6. Pipeline as Holos: generators → transformers → validators → artifact; validators are the extension point for cluster-snapshot checks; output rendered manifests + values to Git/OCI for Flux (OCIRepository/Kustomization/HelmRelease) or Argo CD unchanged.
7. Severity: JSON Schema has none; ytt/Timoni/KCL are blocking-only; helm lint has ERROR/WARNING/INFO. Carry Info/Warning/Blocking as a schema extension (`x-zhi-severity` or CUE attributes); map kubeconform/kyverno/gator/ct results onto it.
8. Cross-value rules: JSON Schema if/then/dependentRequired too weak; offer CEL (cel-go) as user-facing rule language (DevOps already meet it in ValidatingAdmissionPolicy and CRD x-kubernetes-validations), CUE as engine-level fallback.
9. Plugin depth: follow Helm 4 — small fixed set of typed kinds (schema-source, renderer, validator/policy, snapshot-importer, sink/pusher), typed request/response; Wasm runtime (Extism go-sdk, sandboxed, signed) plus subprocess runtime speaking KRM ResourceList so kustomize/kpt/krm-kcl functions run unmodified. Shallower than zhi's current four gRPC types, broader reach.
10. Giterminism (werf) as product rule: validation and pushes computed only from committed inputs + explicitly versioned cluster snapshot; record snapshot identity (cluster, K8s version, CRD/policy digests, timestamp) in the commit/PR.
11. Components map to native switches — Helm `enabled`/`condition` + subcharts, Kustomize `components`, Timoni bundles, Holos components — rather than a new convention.
12. "Plan" view modelled on `nelm release plan` / `kapp --diff-run` / `tk diff`: client-side plan from snapshot (changes, policy failures), optional `helm --dry-run=server` as final gate when reachable; never require the cluster pre-push.
13. Publish zhi schema artifacts (effective schema, snapshot) as OCI artifacts, matching Helm/Timoni/KCL/Flux OCIRepository.
14. Feed snapshot's cluster version and API group/versions into Helm rendering (`--kube-version`/`--api-versions` equivalents) so templates branch as in-cluster.
