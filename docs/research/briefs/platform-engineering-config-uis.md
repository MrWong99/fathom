# platform-engineering-config-uis

## State of the slice (Sept 2026)

"Configure a deployment through a form" has been solved many times, but always inside a bigger product and almost always with only *schema* validation (JSON Schema / OpenAPI), never *target-cluster policy* validation. Dominant pattern: (a) a JSON Schema (Backstage scaffolder parameters, Port userInputs, Helm values.schema.json, Crossplane XRD openAPIV3Schema, Kratix Promise CRD) drives (b) a React form via react-jsonschema-form (RJSF v6.10.0, 2026-09-09, ~15.9k stars) or a bespoke renderer (Rancher questions.yaml, VelaUX ui-schema ConfigMaps, Devtron GUI schema, Cyclops values.schema.json), which (c) either fires a webhook/pipeline that opens a Git PR (Port, OpsLevel, Cortex, Backstage publish:*:pull-request) or applies directly to a cluster (Headlamp, Portainer, Freelens, Helm Dashboard, Cyclops, Rancher). Errors are per-field from the schema validator; secrets are masked (`ui:field: Secret`, Port `type: secret` with AES-256-GCM/public-key encryption, OpsLevel `sensitive`, Cortex `Secret`, Rancher `password|secret`) and redacted from run history. No portal previews rendered manifests before creating the PR. Portals (Backstage v1.54.7 2026-09-11; Port; Cortex; OpsLevel) converge on JSON-Schema forms with jq/CEL conditional fields, dynamic enums bound to catalog entities, manual approval blocks, webhook/GitHub-Actions execution ending in a PR; validation is form-local (pattern/enum/min/max plus async validators such as Backstage `validation.addError()` with `apiHolder`). None import cluster policies.

Pre-commit validation exists only in CLIs: `helm lint/template` (values.schema.json, draft-07; Helm 4 v4.3.0 2026-09-09 adds WASM plugins + SSA, no form UI), `crossplane composition render` + `crossplane resource validate` (fully offline: XRD/CRD/provider schemas + CEL `x-kubernetes-validations`, JSON/YAML output), `score-k8s generate` (offline manifests from score.dev/v1b1), `kubeconform v0.8.0` (OpenAPI only, no CEL, CRD catalog), `kubectl-validate` (apiserver validation code + CEL + `--local-crds`, but v0.0.4 from 2024-05, low activity), `kyverno apply` (policies + resources offline, `--values-file` to stub context; `--cluster` for live lookups). Argo CD ServerSideDiff (stable since v3.1; annotation `argocd.argoproj.io/compare-options: ServerSideDiff=true[,IncludeMutationWebhook=true]` or `controller.diff.server.side: "true"`) is the only mainstream mechanism that evaluates admission/mutating webhooks before sync, and it needs a live API-server dry-run; `argocd-diff-preview` v0.2.14 (2026-08-25) boots an ephemeral kind cluster in CI to render PR diffs. Platform orchestrators (Humanitec commercial; Score score-k8s 0.18.0 2026-09-06; Kratix; Crossplane v2.4.0 2026-08-20; KubeVela v1.11.0 2026-07-20; Radius v0.60.2 2026-09-03) move validation into typed CRDs/XRDs enforced at admission, i.e. still post-apply unless the offline CLIs are used. Devtron v2.2.0 (2026-07-21) is the closest end-to-end competitor (schema GUI + YAML, base/env overrides, locked keys + approval workflow, Dry Run preview, GitOps write-through Argo CD) but is a whole platform with its own CI/CD and charts.

The K8s-UI category is consolidating and imperative: Kubernetes Dashboard archived 2026-01-21 (points to Headlamp); Headlamp v0.45.0 (2026-08-20) is the SIG-UI successor with TS plugin API and workload creation forms but no schema-driven Helm form; Lens OSS dormant (last release 2024-01), OpenLens dead, Freelens v1.10.3 (2026-07-07) the living fork; Helm Dashboard v2.1.3 (2026-08-10) has YAML values editing + manifest diff + Trivy/Checkov; Weave GitOps no stable since Dec 2023 (v0.39.1-rc.1 Jan 2026); Glasskube archived 2026-06-17; Cyclops no release since v0.21.1 (2025-06-26), Git write-back still "roadmap". **Whitespace:** (1) nobody renders a values form from a schema, runs the *rendered output* through the target cluster's actual admission policies (Kyverno, VAP/CEL, Gatekeeper, CRD schemas, ResourceQuota/LimitRange) offline, then opens the PR; (2) nobody snapshots those policies from a live cluster into a portable, versioned "pseudo-cluster" bundle; (3) closest attempts are dead/dormant (Cyclops, Glasskube, Weave GitOps) or whole-platform lock-in (Devtron, Humanitec, Port). The building blocks are mature and Go-native (helm SDK, crossplane CLI libs, kyverno engine, kubectl-validate/apiserver validation libs, cel-go), favouring a Go core with a thin schema-form UI over a new plugin ecosystem.

## Pain-point evidence

- Portal actions execute blind: Port GitOps guide — "No diff/preview shown to user beforehand ... only viewable within the GitHub PR itself after creation" (docs.port.io/guides/all/let-developers-enrich-services-using-gitops/).
- Schema ≠ policy: kubeconform README — "Kubernetes controllers still perform additional server-side validations that are not part of the OpenAPI specifications" (github.com/yannh/kubeconform).
- Admission-aware diff needs live cluster and skips new resources: Argo CD SSD "will execute a Server-Side Apply in dryrun mode for each resource" and "skips new resources" (argo-cd.readthedocs.io diff-strategies).
- PR preview = throwaway cluster in CI: argocd-diff-preview pre-configured mode "saving approximately 60 seconds per execution".
- Chart schemas lack UI hints: Bitnami redis values.schema.json has `$schema: http://json-schema.org/schema#`, descriptions/defaults only, no title/enum/x-* hints.
- Form-first K8s UIs die before GitOps write-back: Cyclops roadmap-only, Glasskube archived 2026-06-17, K8s Dashboard archived 2026-01-21, Weave GitOps no stable since 2023-12.
- Kyverno offline needs hand-written context stubs (`--values-file`/`--set`) or `--cluster` (kyverno.io CLI apply reference).
- `helm lint` ignores deployed values files in schema validation (helm/helm#7756).
- Rancher: "The yaml shown upon selection of the Edit as YAML button is also generated by parsing the questions and is NOT the Values.yaml" — two sources of truth (rancher wiki).
- "Validate before deploy" locked in platforms: Devtron Dry Run only inside its template/approval flow; Humanitec plan-only is commercial.

## Design implications

1. **Pseudo-cluster as first-class versioned artifact** (OCI or directory): CRD/XRD OpenAPI incl. CEL `x-kubernetes-validations`; Kyverno ClusterPolicies/Policies + PolicyExceptions; VAPs + Bindings (+ params); Gatekeeper ConstraintTemplates/Constraints; ResourceQuota/LimitRange per namespace; server version + enabled API groups; namespaces/StorageClasses/IngressClasses/PriorityClasses for pickers. Import via `zhi cluster snapshot --context X`; support diffing two snapshots.
2. **Offline pipeline render → schema → CEL → policy → quota**: Helm SDK (`helm template` semantics incl. subchart schemas), Crossplane `resource validate` approach (apiserver validation lib, unknown-field detection, per-resource JSON), Kyverno Go engine for ClusterPolicy/VAP with snapshot-generated context, cel-go for VAPs. Results isomorphic to PolicyReport + RJSF ErrorSchema: (resource, jsonPath) → values path with Info/Warning/Blocking.
3. **JSON Schema core + UI overlay**: ingest values.schema.json (draft-07, plan 2020-12), XRD openAPIV3Schema, CRD schemas, Score, Rancher questions.yaml → one internal schema; separate overlay (widget/order/group/JSON-Forms-style rules). Auto-generate schema from values.yaml when absent (helm-values-schema-json approach).
4. **Snapshot-fed cluster-aware widgets**: storageclass, namespace, secret/configmap key ref, ingressclass, image (registry policy), cpu/memory bounded by LimitRange/Quota.
5. **GitOps output, never apply**: write values/kustomize patches/Score to a branch, open PR, embed validation report + manifest diff in PR body; optional `argocd app diff --local --server-side-generate` or `kubectl apply --dry-run=server` as authoritative second check. Do not become a cluster-attached UI.
6. **Secrets**: references only in Git (ExternalSecret/SealedSecret/SOPS), `secret` field type masks and never persists plaintext, validation runs with secrets absent.
7. **Small, mostly declarative plugin surface**: Tier 0 built-in Go (schema sources, validators, Git PR output); Tier 1 shell/exec plugins with env-var contract (k9s style) + scanner auto-detection (Trivy, Checkov, conftest, kubeconform); Tier 2 optional WASM or OCI-image validators. Drop four-type gRPC/go-plugin system and own marketplace/mirror unless a concrete need appears; publish packs to Artifact Hub / OCI.
8. **UI**: RJSF (or JSON Forms) with `extraErrors` for policy findings, live validation, side-by-side rendered-manifest + diff pane. Same engine via CLI (`zhi validate --snapshot cluster.tgz --values env/prod.yaml --exit-code`) so PR check and editor agree.
9. **Approval/multi-env**: base + per-env overrides and locked keys as schema `readOnly`/policy; PR reviewer is the approval gate.
10. **Integrate with portals**: Backstage field extension/scaffolder action, Headlamp plugin panel, Port/Cortex/OpsLevel webhook target.
11. **Compose target**: one values/schema model, two renderers (Score dual-impl idea); validate Compose with compose-spec JSON schema + policy checks (image allowlists, no privileged).
