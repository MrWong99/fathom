## 1. Name and one-paragraph thesis

**zhi** (rewrite codename *Ledger*). In the words of the supporter who has to ship release 4.7 into eleven customer clusters this quarter: zhi is a single static binary that takes the Helm chart, Kustomize overlay or Compose file the developers hand over, a signed snapshot of every customer cluster you deploy into, and a form generated from the developers' schema. You fill in the per-environment values; zhi renders the real manifests with the real Helm/Kustomize/Compose engines and runs them through each cluster's *actual* admission posture as captured in the snapshot (CRD schemas and CEL, ValidatingAdmissionPolicy/MutatingAdmissionPolicy, Kyverno, Gatekeeper-generated VAPs, Pod Security, ResourceQuota and LimitRange arithmetic, RBAC of the controller identity, plus the opaque quirks of OpenShift, AKS, GKE, EKS and Rancher encoded as versioned distribution profiles). You get an environment × change matrix telling you which customers this change is safe for, at what fidelity, before the PR exists. Then zhi opens the PR into the folder Argo CD, Flux or your Compose host already watches, with a signed DSSE/SLSA-VSA evidence bundle attached that the customer's auditor can verify offline. It never touches a cluster to apply, never becomes a source of truth, and never needs the internet. Every claim above maps to a whitespace the research found nobody fills (report §1, §8) or a failure class the research found is discovered post-merge today (report §3.1).

## 2. Personas and the transition story

**Developers author the contract, not the deployment.** They keep doing what they do: write the chart, the overlay, the Compose file. zhi asks them for two additional, small, standard-shaped artifacts, following the only clean split the research found (Replicated's KOTS `Config` + Troubleshoot `Preflight`, brief: persona-vendor-to-customer; report §6.2): a **values contract** (`values.schema.json` in JSON Schema 2020-12 with `x-zhi-*` hints, plus `values.cel.yaml` for cross-value rules) and an **environment contract** (`zhi-requirements.yaml`: Troubleshoot-compatible analyzers, `kubeVersion`, required APIs/CRDs, supported distribution profiles). zhi can synthesize a first schema from `values.yaml` defaults and `# @schema` comments (report §9 #10) so the day-one cost is near zero; developers enrich over time. They run `zhi contract lint` in the chart repo's CI and `zhi package publish` to sign and push the package as an OCI artifact. They never see a customer cluster and never need to.

**Consultants and supporters deploy.** They own a GitOps repo (trunk, folder per environment; branch-per-env is the documented anti-pattern, report §2.1). At the customer they run `zhi snapshot import --context customer-prod` with read-only RBAC, sign it, and carry it out as an OCI artifact or air-gap tarball. Back at the desk (or on-site, offline), they open the local web UI over a Git worktree, pick the environment, and fill the form. Cluster-aware pickers (StorageClass, IngressClass, namespace, Secret key, image registry) are populated from the snapshot, so they work air-gapped (report §6.1). Every keystroke re-renders and re-validates against that environment's snapshot and profile in under two seconds (Tier 0, report §5.2). The matrix view shows the same change against all environments in promotion order. When it is green enough, `zhi propose` writes the values layer back with comments preserved, opens the PR, and attaches the evidence bundle. Post-merge, zhi watches Argo/Flux status and tells them whether reality matched the prediction.

**The DevOps transition costs nothing in artifacts.** When a developer starts deploying their own service, they simply pick up the deployer surface for their own environment: same package, same schema, same requirements, same snapshot format. The only thing that changes is who owns `environments/dev.yaml`. This is the same property Replicated gets from one release serving admin-console installs and `helm install` (brief: persona-vendor-to-customer §5), without the SaaS control plane or the in-cluster admin console that KOTS reviews complain about. A platform team in the middle can introduce a third role (environment owner who curates snapshots and profiles) without any new file format.

**Regulated procurement is a persona too.** The security officer at a bank or hospital never runs zhi; they receive its output. So evidence is a first-class product surface: signed reports, deterministic digests, SBOMs, a FIPS build, zero egress, and role separation (developer-signed contract versus deployer-filled values) that the regulated-customer brief lists as procurability requirements (brief: gap-deployer-environments-openshift-managed-regulated, Part 2).

## 3. Domain model

**Entities and relationships.**

| Entity | Identity | Relationships | Lives in |
|---|---|---|---|
| **Workspace** | Git repo root + `zhi.yaml` | 1..n Packages, 1..n Environments, 1 Lockfile | Git |
| **Package** (developer contract) | OCI ref + digest (`ghcr.io/acme/app:4.7.0@sha256:…`) | wraps chart/overlay/compose + values contract + environment contract + Components | OCI (signed); pinned in Git lockfile |
| **Component** | name, unique within Package | dependency DAG; maps to Helm `condition`/subchart, Kustomize `Component`, Compose `profiles` | Package |
| **Environment** | name, unique within Workspace | promotion position (`promotesTo`), matrix dimensions (tenant, region, tier), 1..n Targets, GitOps binding (tool, path, merge layer), Snapshot ref per Target, Profile ref, secret-store bindings | Git (`environments/*.yaml`) |
| **Target** | cluster identity (API server CA fingerprint + UID of `kube-system` ns) or Docker host identity (engine ID) | belongs to 1 Environment; has 0..n Snapshots over time | Git (identity only) |
| **Snapshot** | content digest; provenance (target, capture time, capturing identity, server version, per-layer hashes) | of exactly one Target; referenced by Environment via digest; may carry a *declared overlay* | OCI / air-gap tar; cached under `.zhi/snapshots/<digest>/` (gitignored) |
| **Profile** (distribution profile) | `openshift-4.20`, `aks-automatic-2026-06`, versioned with changelog | referenced by Environment; shipped built-in, overridable by OCI ref | Binary + OCI |
| **ValuesLayer** | file path + merge position (base < variant < env < cluster < runtime `substituteFrom` < machine-managed) | discovered from controller CRs; keys addressed by JSON Pointer | Git |
| **Change** | Git branch/worktree diff (set of ValuesLayer edits) | evaluated against each Environment → Report | Git (branch) |
| **Finding** | stable ID = hash(rule id, environment, resource identity, instanceLocation) | belongs to one Report; back-links to ValuesLayer pointer and to source `file:line:col` | Report |
| **Report** | deterministic digest of canonical JSON | Change × Environment; contains Findings, fidelity tags, snapshot/profile/package digests | Git (PR check output) + OCI referrer |
| **Evidence** | DSSE envelope digest | wraps a Report as in-toto Statement with SLSA VSA v1 predicate | OCI referrer on the Snapshot and on the Package; PR check |
| **Lockfile** (`zhi.lock`) | one per Workspace | pins Package digests, Snapshot digest per Environment/Target, Profile digests, engine-binary digests (Kyverno CLI, cosign) | Git |

**Addressing.** Values are addressed by RFC 6901 JSON Pointer within a named layer file (`environments/prod/values.yaml#/database/replicas`), never by the flat slash paths of the current zhi, whose `[a-z]` segment regex cannot express camelCase Kubernetes keys or list indices (audit brief §1.1). Rendered resources are addressed by `<rendered file>#<apiVersion>/<kind>/<namespace>/<name>` plus a JSON Pointer into the object; Compose services by `<compose file>#/services/<name>` plus pointer. The canonical finding record is the JSON Schema 2020-12 output unit (`instanceLocation`, `keywordLocation`) extended with `severity`, `tier`, `engine`, `environment`, `sourcePosition`, `wouldFailAt` (admission | scheduling | runtime) and `fixHint`; apiserver `field.ErrorList`, CEL `fieldPath`, Kyverno PolicyReport results and Rego violations are all normalized into it (report §9 #11; brief: schema-validation-tech §2). This directly fixes the current `ValidationResult` that has no `Path` and forced a `Metadata["path"]` side channel (audit brief §1.3).

**What lives in Git, and what does not.** Git holds everything a reviewer must be able to reproduce: workspace config, environments, values layers, lockfile with digests, and the PR check output. OCI holds the bulky, signed, immutable things: packages, snapshots, profiles, evidence, engine binaries. Nothing holds secrets: values carry typed references `ref://<store>/<path>#<key>[@version]` rendered to ESO `ExternalSecret` by default, SealedSecret or SOPS optionally, and validation runs with secrets absent (report §9 #14). Cluster state is *never* a store of record; the snapshot is a read-only copy with a capture time, treated like a lockfile: reports cite it, and Blocking findings cannot be cleared against a snapshot older than the environment's `maxSnapshotAge` (report §5.3).

**The environment × change validity matrix** is derived, not stored: for a Change, zhi evaluates `f(package, values layers, snapshot, profile)` per Environment and shows rows in promotion order grouped by tenant, columns per Component or per changed key, cells carrying worst severity, fidelity tier, and staleness (brief: environments-secrets-drift, design implication 3). A second matrix, **package × environment compatibility**, evaluates only the environment contract (requirements) against each snapshot and answers the consultant's quarterly question "which customers can take 4.7?", the thing Distr publishes as vendor-authored compatibility reports and zhi instead computes (brief: persona-vendor-to-customer, Distr row).

## 4. Architecture

**Binaries and packages.** One module, one binary `zhi` (plus a `zhi-fips` build variant via `GOFIPS140`), `CGO_ENABLED=0`, no `replace` directives, which the embedding audit confirms is achievable for the whole k8s.io/Helm/Kustomize/compose-go/OPA/Gatekeeper-driver set as long as `k8s.io/kubernetes` is never imported (brief: gap-go-embedding-and-license-audit §0, §5).

```
cmd/zhi                      Cobra CLI: snapshot, env, validate, propose, evidence, serve, lsp, mcp, mirror
internal/model               entities above; JSON Pointer addressing; yaml.v3 Node round-trip
internal/discover            Argo/Flux/Kargo/Compose CR + layout discovery → ValuesLayers per Environment
internal/contract            schema ingest (values.schema.json, # @schema, XRD/CRD, Compose vars) → internal 2020-12; x-zhi vocabulary
internal/render              helm.sh/helm/v4 (snapshot-fed Capabilities + lookup), kustomize/api/krusty, compose-go/v2; exec adapters (ResourceList) for Timoni/ytt/flux build
internal/snapshot            importer (client-go discovery + dynamic client, Docker API), on-disk format, redaction, OCI push/pull, air-gap export/import, cosign verify chokepoint
internal/profile             distribution profiles as data + Go emulators (sccmatching, Autopilot ratios, AKS safeguard mutators, Karpenter NodePool fit)
internal/sim                 ordered apiserver-chain emulation (Tier 0-b): expand → schema/CEL → LimitRanger → PSA → quota → MAP → VAP → engines → webhook match → RBAC
internal/sim/vendor          ~2k LOC vendor-forked LimitRanger, RBAC RulesAllow, quota evaluators from kubernetes@v1.37.0 (Apache header + NOTICE)
internal/engines             kyverno CLI exec with generated Context/Values/UserInfo; Gatekeeper k8scel driver + OPA for Rego templates; Troubleshoot analyzers
internal/findings            output-unit normalization, severity map, lineage back-map, SARIF/PolicyReport/JSON emitters
internal/matrix              Change × Environment evaluation, staleness, promotion gating
internal/evidence            canonical report digest, DSSE + SLSA VSA v1 statement, in-toto test-result predicate, hash-chained audit log
internal/git                 worktree, comment-preserving write-back, PR/MR (GitHub/GitLab), commit trailers, commit status
internal/ui                  Go http server, htmx shell, embedded JSON Forms bundle, SSE
internal/lsp, internal/mcp   output surfaces generated from the same command table
pkg/zhiplugin/resolver/v1    the one gRPC lane (secret stores, credentialed cloud collectors); first-party compiled in
```

**Data flow, edit to PR.** (1) `zhi serve` opens a Git worktree, runs discovery, and builds the ValuesLayer map per Environment with effective values and their source layer (report §9 #2). (2) The UI posts an edit; zhi applies it to the in-memory yaml.v3 Node tree, validates the values contract (schema + CEL over `values`), renders for the selected Environment, runs Tier 0, and returns findings as JSON Forms `additionalErrors` plus the rendered diff (dyff embedded). The current zhi's "mutate, validate, revert" inline pattern is kept verbatim because it means zero duplicated client-side rule logic (audit brief §3.2). (3) On "evaluate all", the matrix is computed for every Environment. (4) `zhi propose` writes changed layers back preserving comments and ordering (machine-managed fields such as image-automation markers are read-only, report §9 #13), commits with trailers, opens the PR, posts the report as a check and the matrix as a collapsible PR comment in argocd-diff-preview style (brief: inner-loop-pseudo-cluster #13), and pushes the Evidence as an OCI referrer. (5) Post-merge, `zhi watch` subscribes to Argo application status / Flux conditions and records "predicted vs observed" in the audit log (report §9 #24).

**Render → validate pipeline, in this order** (report §5.3; brief: cluster-state-import #3). Discovery presence check first (removed/deprecated APIs on the target minor, replacing pluto). Then render with the real engine, Helm `Capabilities` and `lookup` fed from the snapshot (a chart that looks up a kind absent from the snapshot gets a Warning). Then expand workloads to Pods (gator-expand/Kyverno-autogen style), because PSA and quota apply to Pods, not Deployments, and "Deployment accepted, Pods rejected" is failure class 7 (report §3.1). Then strict fields + structural schema + defaulting + CRD CEL via kubectl-validate's `customresource.NewStrategy` path (confirmed to run CEL, brief: gap-go-embedding §0.3). Then NamespaceLifecycle, LimitRanger (mutate then validate), PSA with namespace labels plus the profile's declared exemptions, ResourceQuota `CheckRequest` against `status.used` with a stale-quota Warning, MAP then Kyverno mutations (showing the mutated object as "what the cluster will store"), then VAP/Kyverno/Gatekeeper validation, webhook match prediction (which webhooks fire; logic unknown, badge), and finally RBAC `RulesAllow` for the controller's identity. Distribution profile hooks run at the admission-mutation and scheduling stages. Severity mapping: Deny/Enforce/schema/CEL → Blocking; Warn/Audit/stale quota/best-effort native checks/webhook predictions → Warning; deprecations and annotations → Info (report §9 #9).

**Snapshot format.** Own layout, because `kwokctl snapshot export` omits exactly the objects that matter by default (brief: gap-k8s-offline-fidelity-facts §7) and no other substrate is complete (report §10.1). On disk and inside the OCI artifact:

```
provenance.json          target identity, context, serverVersion, capturedAt, capturedBy, layer hashes, importer version, feature gates observed (MAP v1 vs v1beta1)
discovery/               APIGroupDiscoveryList JSON
openapi/api/<v>.json, openapi/apis/<g>/<v>.json      kubectl-validate layout, keyed by ?hash= for incremental refresh
crds/                    raw CRDs (x-kubernetes-validations, defaults, pruning kept)
admission/static/        VAP/VAPB, MAP/MAPB in the 1.37 manifest-based (.static.k8s.io) file form + paramKind objects
admission/webhooks/      Validating/MutatingWebhookConfiguration metadata only, flagged cannot-evaluate
engines/kyverno/ engines/gatekeeper/ engines/kubewarden/     policies, exceptions, templates, constraints, Config/SyncSet, generated VAPs, engine versions
namespaces/<ns>/         Namespace (labels incl. PSA and OpenShift SCC ranges), ResourceQuota (spec+status), LimitRange, default NetworkPolicies
catalogs/                StorageClass (+CSIDriver), IngressClass, GatewayClass, PriorityClass, RuntimeClass, SCCs, ComputeClass/NodePool/NodeClass
rbac/                    Roles, bindings, SelfSubjectRulesReview for the deploying identity
inventory/               allowlisted names/keys of Secrets/ConfigMaps (never values), ServiceAccounts, Services/Ingress/Routes hosts, existing workloads for oldObject
gitops/                  Argo Applications/ApplicationSets, Flux Kustomizations/HelmReleases, (Cluster)SecretStore names, Sealed Secrets cert, Kargo Stages
nodes/                   optional: allocatable, labels, taints, per-node request aggregates
declared.yaml            "declared, not observed" overlay: PSA AdmissionConfiguration exemptions, static policies handed over by the operator, webhook stubs, Rancher PSACT, profile id
```

Each layer is redactable and independently hashed; the importer degrades gracefully ("quota unknown: forbidden on resourcequotas") and records what it could not read (report §9 #4, #5). The OCI shape reuses the current zhi's ORAS client and custom media types (`vnd.zhi.snapshot.layer.v1+json` per layer, one config blob), signed as a cosign v3 protobuf bundle, and the air-gap tarball reuses the current `zhi-mirror` `airgap` format (oci-layout + `bundle.json` + digest-verified blobs), which the audit rates as solid, hardened code (audit brief §2.6). Snapshots move through Zarf, oc-mirror or Hauler like any other OCI artifact (brief: gap-deployer-environments, Part 2 #8).

**Fidelity tiers shipped in v1.** Tier 0-a (schema, discovery, CRD CEL) and Tier 0-b (full ordered emulation with engines) are the default on every save. Tier 2 (live `kubectl --dry-run=server`, Argo `server-side-diff`, `flux diff kustomization`) is an optional final gate when a kubeconfig exists, and its findings are labelled separately with an explanation of the delta (side-effect webhooks, mutations) rather than merged (report §5.3). Tier 1 (envtest/KWOK hydrated from the snapshot) is *not* in v1: boot times are unmeasured, it needs 150–400 MB of per-minor binaries, and it breaks the single-static-binary story (brief: inner-loop-pseudo-cluster, uncertainties). Every finding carries its tier; the UI never says "will apply", only "schema-valid / apiserver-valid (CRDs exact, native approximate) / policy-valid (N rules skipped needing live data)" with badges for unobservables (report §5.3).

**UI approach.** Go `net/http` with the current zhi's server-rendered htmx shell and its already-solved middleware chain (CSRF double-submit, per-request CSP nonce, ETag-outside-HTML, gzip-outside-ETag, SSE flusher unwrap; audit brief §3.2) for the matrix, findings, diff, PR and evidence pages. The values form is the one place a JS renderer is unavoidable: no Go-native JSON-Schema-to-form renderer exists (brief: schema-validation-tech, uncertainties), so zhi embeds a prebuilt, pinned JSON Forms bundle as a static asset (committed, hashed, no runtime build, no CDN, zero egress). JSON Forms is chosen over RJSF because its SHOW/HIDE/ENABLE/DISABLE rule model maps directly to component toggles and conditional sections (brief: schema-validation-tech #8), while RJSF's Ajv2020 support is documented as limited. Client-side validation is advisory; the Go core is authoritative and pushes output units into `additionalErrors`. Findings map back to fields three ways: schema and `values`-CEL findings already carry a values pointer; rendered-manifest findings use developer-declared `x-zhi-targets` (schema field → rendered JSON pointer, the Glasskube `targets` idea, brief: persona-vendor-to-customer §1) when present, and otherwise a scalar-fingerprint match of the flagged rendered value against effective-values leaves; unresolved findings anchor to the resource with its rendered path. Perturbation-based lineage is a phase-2 spike.

**Surfaces.** CLI (`zhi validate --env prod --exit-code`, exit codes owned by zhi so the Kyverno-CLI-exits-0 trap cannot recur, report §3.3); CI mode emitting JSON, SARIF and PolicyReport and posting commit statuses; a gitops-promoter `CommitStatus` provider and Kargo `git-wait-for-pr` compatibility (report §9 #25); an LSP server for diagnostics, hover and code actions applying `proposedValue`, plus `.zhi/schema.json` with the yaml-language-server modeline for free editor support (report §9 #28); an MCP server (stdio + streamable HTTP, loopback, read-only default) generated from the same command table as the CLI, not hand-written a fourth time (audit brief §3.6). All three are output surfaces over one core, never extension points.

## 5. The developer ↔ deployer contract

Two developer-authored artifacts, both standard-shaped so they keep working without zhi at runtime: Helm 4 enforces `values.schema.json` itself (2020-12 is the default draft when `$schema` is absent, brief: gap-go-embedding §4.3), and `kubectl preflight` consumes the Troubleshoot-compatible requirements (brief: persona-vendor-to-customer, design implication 11).

**Values contract** (`values.schema.json`, consumed and emitted; `x-zhi-*` registered as a custom vocabulary so hints are type-checked by zhi and ignored as annotations by everyone else):

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "properties": {
    "persistence": {
      "properties": {
        "storageClass": {
          "type": "string",
          "x-zhi-cluster-ref": "storageclass",
          "x-zhi-requires": { "accessModes": ["ReadWriteMany"] },
          "x-zhi-targets": ["/spec/volumeClaimTemplates/0/spec/storageClassName"],
          "x-zhi-component": "shared-uploads"
        }
      }
    },
    "database": {
      "properties": {
        "passwordRef": { "type": "string", "format": "zhi-secret-ref", "x-zhi-ui": { "widget": "secret-ref", "store": "primary" } },
        "replicas":    { "type": "integer", "minimum": 1, "maximum": 20, "x-zhi-ui": { "group": "Database", "order": 20 } }
      }
    }
  }
}
```

**Cross-value rules** (`values.cel.yaml`, helm-cel pattern with the VAP variable set; evaluated through `k8s.io/apiserver/pkg/cel/environment`, never a second CEL runtime, brief: gap-go-embedding §0.2; stored in a shape promotable to a `ValidatingAdmissionPolicy` later, report §9 #12):

```yaml
apiVersion: zhi.dev/v1
kind: ValuesPolicy
rules:
  - id: ha-needs-rwx
    expression: "!values.ha.enabled || has(values.persistence.storageClass)"
    fieldPath: ".persistence.storageClass"
    severity: Blocking
    message: "HA mode needs a shared (RWX) storage class"
  - id: replicas-fit-quota
    expression: "values.database.replicas * quantity(values.database.resources.requests.cpu).asApproximateFloat() <= env.quota.available('cpu')"
    severity: Warning
    message: "Requested CPU exceeds remaining namespace quota in this environment"
```

**Environment contract** (`zhi-requirements.yaml`; analyzer vocabulary is Troubleshoot's, embedded as a Go library and extended where the research found gaps: RWX capability via CSIDriver, quota headroom, PSA level, CRD *version*, IngressClass/GatewayClass, egress reachability; requirements may reference the deployer's chosen values, report §6.1):

```yaml
apiVersion: zhi.dev/v1
kind: Requirements
kubeVersion: ">= 1.31.0-0"
profiles: { supported: [vanilla, openshift-4.18+, aks-standard, eks-auto-mode], unsupported: [gke-autopilot] }
requiredAPIs: [ "cert-manager.io/v1/Certificate", "gateway.networking.k8s.io/v1/HTTPRoute" ]
analyzers:
  - storageClass: { storageClassName: "{{ .values.persistence.storageClass }}", capabilities: [ReadWriteMany], strict: true }
  - podSecurityLevel: { namespace: "{{ .env.namespace }}", maxEnforce: baseline }
  - resourceQuotaHeadroom: { namespace: "{{ .env.namespace }}", cpu: "{{ .rendered.totals.requests.cpu }}", memory: "{{ .rendered.totals.requests.memory }}" }
  - imagePullSecret: { registryName: "{{ .values.image.registry }}" }
```

The package also carries `Chart.yaml kubeVersion` and a generated Troubleshoot `Preflight` Secret so Replicated users get value without zhi. Components are declared once (`x-zhi-component`) and bound to native switches (Helm `condition`, Kustomize `Component`, Compose `profiles`); the dependency DAG, cycle detection and cascade semantics come from the current zhi's `ComponentManager` re-addressed to manifest identity (audit brief §1.5). The developer signs the package; the deployer's values are signed separately by the evidence step, satisfying the role-separation line in the procurability checklist.

## 6. GitOps integration

**Discovery.** zhi reads the controller CRs in the workspace and maps every values key to file + pointer + merge layer (report §9 #2): Argo `Application.spec.source(s).helm.{valueFiles,valuesObject,parameters,fileParameters}`, `kustomize.{images,replicas,patches}`, ApplicationSet git-files generator globs and cluster-Secret labels, `sourceHydrator.drySource`; Flux `HelmRelease.spec.{values,valuesFrom,chart.spec.valuesFiles}` in documented precedence, `Kustomization.spec.postBuild.substitute(From)` with `${VAR:=default}` strictness, images and patches; Kargo `Stage`s for promotion order; Compose `-f` chains, `.env`, `env_file`, profiles. Inputs that live only in the cluster (Flux `substituteFrom` ConfigMaps, Argo cluster-Secret labels) come from the snapshot's `gitops/` layer, redacted but keyed, so the effective value is reproducible from Git plus snapshot (brief: environments-secrets-drift, pain point 4). The effective-value explorer shows, per environment, which layer won (failure class 16, report §3.1). Environments are inferred on first run from ApplicationSet generators, `clusters/<env>/` folders, Kargo Stages and Compose file naming, then written to `environments/*.yaml` for the user to confirm.

**Producing the PR.** DRY-repo-centric is the primary write target because it works for Flux, Compose and Kargo OSS alike; hydrated branches (`hydrateTo`, `environment/<env>-next`) are supported as a validation *read* path and as an optional target (report §10.1 verdict on primary Git flow; owner decision Q1). `zhi propose` creates a branch, rewrites only the affected layer files through the yaml.v3 Node tree (comments, ordering and image-automation markers intact), commits with trailers, opens the PR/MR via the GitHub/GitLab API, posts the report as a check run with SARIF annotations at `file:line:col`, and posts the matrix as a collapsible comment. If Kargo is present, the PR is exactly what `git-wait-for-pr`/`git-merge-pr` wait on; if gitops-promoter is present, zhi acts as a `CommitStatus` provider on the hydrated branch (report §4.1, §9 #25). Write-through to a controller-synced branch without review is refused by default (owner decision Q13); a dev-environment override exists but is recorded in the audit log.

**Provenance recorded.** Commit trailers in the Source Hydrator style: `Zhi-Package: <oci ref>@sha256`, `Zhi-Snapshot-<env>: sha256`, `Zhi-Profile-<env>: openshift-4.20@sha256`, `Zhi-Report: sha256`, `Zhi-Fidelity: T0b`, `Zhi-Author: <git identity or OIDC subject>`. The Evidence bundle (DSSE over an in-toto Statement with the SLSA VSA v1 predicate: `verificationResult`, `verifier`, `timeVerified`, `resourceUri` = rendered-manifest digest, `policy` = snapshot + profile + package digests) is pushed as an OCI referrer of the snapshot and attached to the check output (brief: gap-deployer-environments, Part 2 #1). Reports are deterministic: identical inputs yield identical digests, which is what lets evidence be reused across customers who share a profile (procurability checklist).

**Post-merge.** `zhi watch` subscribes to Argo application status and Flux conditions (or polls the commit-status providers), correlates hydrated SHA ↔ dry SHA (git notes) ↔ report, and appends "predicted vs observed" to the hash-chained audit log. A mismatch (a Blocking that zhi missed, or a Warning that did not fail) is the calibration signal for profiles and the metric the deployer persona cares about: Blocking findings caught pre-push and the "would have failed at" stage (report §9 #31). Rollback stays `git revert`; zhi warns about non-revertible effects (Helm hooks, immutable fields, PVC storageClass) and about in-cluster rollbacks that diverge from Git (brief: gitops-controllers, design implications).

## 7. Docker Compose

Compose is the second first-class target with the same model, not an exporter: compose-go v2 is the renderer (embedded; `LoadProject` with interpolation off to run `template.ExtractVariables`, giving the editable value set with defaults and required flags, then reloaded with the UI mapping), and the Compose-spec 2020-12 schema plus its ~28 consistency checks are the schema layer (brief: docker-compose-landscape, design implication 1). Environment, Target, Snapshot, Profile, matrix and evidence are identical; the GitOps binding is "the repo Portainer polls, Komodo syncs, or CI deploys over SSH". Write-back goes only to `.env`, `compose.<env>.yaml` overrides and typed `x-zhi-*` blocks so plain `docker compose up` keeps working (report §9 #17).

**The host snapshot** (`zhi snapshot import --docker-context customer-edge-3`, one read-only Docker API pass; same shape from Portainer's API or Komodo Periphery): Engine/API and Compose versions, OS/arch, cgroup version, rootless/userns-remap, seccomp/AppArmor defaults, default address pools, CPU/memory/GPU capacity, listening host ports (published ports of running containers), existing networks, volumes, containers and Compose projects, images with digests, registry reachability, bind-source existence and permissions, swarm/podman flags, and the host's policy pack if one exists (report §5.1 Compose analogue). The declared overlay carries what the API cannot see (proxy egress rules, firewall-owned ports).

**Host-aware checks** cover the runtime-only failures the research lists (failure class 17): strict interpolation (referenced variable absent → Blocking, defaulted → Warning; empty result in `image`, `ports`, `volumes` → Blocking), published-port collision against the snapshot and across services and projects, missing bind sources, cross-project `container_name` collision, `cpus`/`mem_limit` versus capacity, `gpus` without GPU, `deploy.*` with swarm disabled (Warning), Swarm- or podman-unsupported attributes when that flavour is set, version gates (`env_file.required` ≥ 2.24, `pre_start` ≥ 5.3), image tag not cached with registry unreachable (Info) or nonexistent by HEAD manifest when online (Blocking). Policy is data over the normalized compose-go JSON: the default pack mirrors Portainer's security dimensions (no privileged, no host PID/net/IPC, binds under allowed roots, no added capabilities, explicit tags, healthcheck required) and is evaluated by the same CEL environment used for Kubernetes, with Rego via embedded OPA as the second option for teams already on Conftest/KICS. Secrets resolve at export through `sops exec-env` or provider CLIs, since SOPS is the one model identical for Compose and Kubernetes (report §4.7). Podman/Quadlet is a profile on the Kubernetes path (unsupported kinds and fields → Blocking, quadlet generator `--dryrun` when a `.kube` unit is emitted); Ansible and Nomad are out of scope by the regulated brief's verdict (Part 3).

## 8. Plugin depth

The owner asked how deep the plugin system must be. The evidence from every brief is "shallow": the tools that thrive extend through data, CEL, and digest-pinned CLI binaries; sidecar/gRPC plugins in the deploy path are universally painful (Argo CMP #15006, Kustomize plugins alpha for five years), Wasm ships slowly (Helm 4.1–4.3 added nothing, Extism Go SDK untagged 18 months), and the extensibility that actually mattered commercially was custom collectors/analyzers and field renderers (report §7.1; brief: plugin-architectures). The answer is a fixed Go core plus **one loadable kind in v1** and a second held in reserve.

| Concern | Mechanism | Why |
|---|---|---|
| Source loaders (YAML/JSON/TOML/env, Helm values, Kustomize, Compose, Argo/Flux/Kargo discovery) | Fixed Go core, configured by file patterns and layer maps | Need source positions and comment-preserving write-back; Renovate regrets losing positions in its config-only managers (report §7.2) |
| Renderers | Fixed: Helm v4 SDK, krusty, compose-go. Exec adapters speaking KRM `ResourceList` for Timoni/ytt/KCL/Pkl/`flux build` | "Valid in zhi" must equal "valid for the controller"; the exotic languages need CGO/JVM/Node and are excluded from the core (report §4.2) |
| Validators and policies | Data (schema packs, imported VAP/MAP/Kyverno/Gatekeeper manifests evaluated untranslated), CEL with a fixed host library, digest-pinned CLIs (Kyverno, kwctl, gator, flux-schema, Trivy/Checkov auto-detected on PATH) | Engines need in-process performance and a shared CEL type environment; Kyverno's module has a PSA fork replace and 10 GHSAs in 2026, so it is isolated as a subprocess (report §9 #7) |
| Cluster and host importers | Fixed Go core (dynamic client, Docker API, Portainer/Komodo/Rancher/OpenShift API adapters); Troubleshoot collectors as input format | Importer correctness is the product; every brief wants it first-party (report §7.2) |
| Distribution profiles | Data (versioned OCI artifacts with changelog) + small Go emulators in core | Opaque platform admission must be maintained from vendor docs and auditable by version (brief: gap-deployer-environments, cross-cutting finding) |
| Secret resolvers and credentialed collectors | **`resolver/v1`** over go-plugin gRPC, first-party compiled in, external via signed OCI + lockfile | The one place every brief still wants a process boundary: long-lived, credentialed, heterogeneous (Vault, KMS, Infisical, cloud policy APIs like Binary Authorization); Vault itself chose isolation over Wasm (report §7.3) |
| Pure third-party checks CEL cannot express | **`check/v1`**, phase 2, wazero with a zhi-owned ABI or exec with the `ResourceList`/output-unit contract, OCI + Sigstore, declared capabilities | Kubewarden proves the shape; demand is unproven, so it waits (report §7.3) |
| Targets and publishers | Fixed: Git branch + PR (GitHub/GitLab), OCI push, commit status, gitops-promoter CommitStatus, PR comment; templates for PR body | Two providers cover the company's estate; more are pull requests to core |
| UI panels, LSP, MCP | Output surfaces, not extension points; widget ids and rules live in the schema vocabulary | Grafana and Backstage are still fighting sandbox and versioning debt from pluggable UIs (report §7.1) |

**Explicitly not pluggable:** the UI, the store (Git is the store), transforms in the GitOps path (what Flux forbids and Argo suffers from), the snapshot format and importer, the apiserver-chain emulator, the finding record, and the evidence format. Versioning follows Terraform/Crossplane/LSP: `zhi.plugin.v1` proto package, additive RPCs gated by capability flags, tolerant enums, plugins request schemas from the host. Distribution keeps the current OCI client and lockfile, adds a curated krew-index-style catalog file, and ships no marketplace, ratings or search until third-party plugins exist (report §9 #20).

**Compared with today's four gRPC types.** `config` (4 methods) survives conceptually as the in-process loader/contract interfaces; `transform` is dropped outright; `store` (27 methods, capability negotiation, CAS, ACLs, encryption) is superseded by Git and secret references; `ui` (25 methods × 8 implementations) collapses into one in-process controller with generated LSP/MCP projections. The 10,790 lines of generated protobuf and eight hand-written client/server pairs that the process boundary cost the current codebase (audit brief §2.1, lesson 6) shrink to one small `resolver/v1` proto. The meta-plugin SDK (delegate/merge/mirror) solves a problem the rewrite does not have and goes.

## 9. What to carry from the current zhi and what to drop

**Carry, mostly verbatim** (audit brief §7.1): the Info/Warning/Blocking triad (it maps 1:1 onto VAP Deny/Warn/Audit, Kyverno Enforce/Audit, Troubleshoot fail/warn/pass + `strict`); the `ComponentManager` dependency graph, cycle detection, mandatory-with-transitive-dependencies pre-enabling and cascade-disable refusal, re-addressed to manifest identity (§1.5, "best code in the repo"); `apply.go`'s subprocess handling (process groups, `WaitDelay`, pipe-drain ordering, 1 MiB scanner, non-zero exit as a result), now driving the Kyverno CLI, cosign, git and exec adapters (§4.3); `drift.go` + `diff.go`, generalized from "rendered vs files on disk" to "rendered vs snapshot inventory" and "snapshot vs snapshot" (§4.4); the mutate-validate-revert inline UX and the severity-grouped findings page with source-location links added (§3.2); the htmx server and its middleware chain including the SSE log pane (§3.2, §7.1); the ORAS-based OCI client with custom media types, multi-platform index and atomic install (§2.6); the digest-pinning lockfile (§2.6); the `zhi-mirror` air-gap export/import and OCI-layout storage, promoted from "defer" to core because this angle *is* regulated customers (§2.6); `launch/audit.go`'s binary integrity hygiene for downloaded engine CLIs and policy bundles (§2.4); the test conventions (`-race -count=1`, fmt-diff CI, golden fixtures, `t.Parallel()` from day one) (§6); and the Vault HTTP client plus `store.writeonly` concept as the seed of secret references (§5.1).

**Drop** (audit brief §7.1, §7.2): the flat slash-path tree and its `[a-z]` regex (cannot express Kubernetes keys or list indices); `Val any` and its 330 lines of coercion; the `Metadata["path"]` convention; non-serializable `Value.Validators`; Yaegi-interpreted Go in config files (remote code execution from a PR, lesson 3); the four gRPC plugin types, JSON-over-protobuf encoding and generated stubs; `transform.Plugin` and `ValidatePolicy`; the 27-method store interface and the plaintext JSON fallback store; the TUI and `RequiresTTY`; the httpapi mirror; the marketplace server, ratings, advisories and publisher tiers; `text/template` + Sprig as the Kubernetes/Compose bridge (string interpolation with no schema awareness is the gap the rewrite closes, §4.2); `fileACL`/`fileMode` side-effecting template functions; the meta-plugin SDK; and the unwired Sigstore stack (1,236 LOC with zero callers, signer identity hardcoded to `"keyless-identity"`, lesson 7). Verification is rebuilt as a single chokepoint that execs a digest-pinned cosign v3 with `--offline --trusted-root` in v1, and embedding via sigstore-go is reconsidered only after the FIPS spike. Every one of the audit's ten lessons has a line item above; the two that shape this design most are "put the path in the finding" and "build toward observed failure".

## 10. MVP, phase 2, phase 3

**MVP: what a consultant can do end to end.** Import a Kubernetes snapshot from a customer cluster with read-only RBAC, sign it, export it as an air-gap tarball, import it at the desk, and pin it to an environment. Load a Helm-chart package (schema synthesized if absent), define environments with promotion order and tenant/region dimensions, and see the effective values per environment from Argo or Flux layouts. Edit values in the form with snapshot-fed pickers, get Tier 0-a + 0-b findings in under two seconds (CRD CEL, VAP/MAP, PSA, LimitRange, quota arithmetic, RBAC, Kyverno via CLI, Gatekeeper via its generated VAPs, webhook match prediction), plus the vanilla and OpenShift profiles (SCC matching, UID range placeholders, Route host collisions, IDMS/ITMS rewrite). See the environment × change matrix and the package × environment compatibility matrix. Open a PR with comment-preserving write-back, SARIF check, matrix comment, provenance trailers and a DSSE/VSA evidence bundle verifiable offline. Run the same thing headless in CI with reliable exit codes. Ship as one static binary plus a `GOFIPS140` variant, SBOMs (CycloneDX 1.6, SPDX 3.0.1) and SLSA provenance from the release pipeline, zero egress by default. Kustomize rendering is in (krusty is cheap); Compose, Rego, LSP, MCP, Tier 2 live checks and the other cloud profiles are not.

**Phase 2.** Docker Compose target with host snapshot and policy pack; AKS (Deployment Safeguards mutators), GKE Autopilot (Warden constraints, resource ratios), EKS Auto Mode (NodePool fit, Pod Identity) and Rancher (PSACT via management API, project quotas) profiles; embedded OPA for Rego ConstraintTemplates with snapshot-fed inventory; Tier 2 live gates (Argo `server-side-diff`, `flux diff`, `kubectl --dry-run=server`) and post-merge watch with predicted-vs-observed audit entries; LSP and MCP generated from the command table; ESO/SealedSecret/SOPS rendering and `resolver/v1` for Vault; perturbation-based value lineage; interoperable exports (kubeconform dir, Kyverno context files, gator inventory, Troubleshoot Preflight Secret); hash-chained audit log export for auditors.

**Phase 3.** Tier 1 apiserver backend (envtest or KWOK hydrated from the snapshot with manifest-based admission) once benchmarked; `check/v1` Wasm/exec validators if demand appears; scheduler-framework fit against snapshot nodes; Kubewarden via kwctl; CUE import/export for Timoni/Holos shops; Podman/Quadlet profile; curated plugin catalog; optional private-Sigstore signing for fully offline keyless flows.

**Size.** The current zhi is 42k non-test Go LOC of which roughly 20k is plugin, store, TUI and marketplace infrastructure that does not return (audit brief §0). The MVP above is estimated at 22–28k non-test Go LOC (importer and snapshot ~4k, sim chain plus ~2k vendor-forked upstream code ~6k, render and contract ~4k, discover/git/evidence ~4k, UI ~4k, CLI/matrix/profiles ~4k) plus ~2k of front-end glue around the vendored JSON Forms bundle, with tests near 1:1 per repo convention. For a 1–2 person team that is 7–9 months to a usable MVP, with the first four months producing the CLI-only vertical slice (import → render → validate → PR) before any UI. Phase 2 is another 12–15k LOC and 4–5 months; phase 3 is open-ended and demand-driven. The profiles are the ongoing cost: each managed distribution changes several times a year, so budget a recurring day per profile per quarter.

## 11. Risks, unknowns, and the lab spikes required before committing

The research is explicit that several load-bearing claims were read from source, not measured (report §1 last bullet; §10.2 Q16). These spikes gate the architecture freeze; each is a two-to-five-day task with a pass/fail criterion.

- **SPIKE-CEL-CRD**: kubectl-validate's `pkg/validator` on a CRD with a deliberately failing `x-kubernetes-validations` rule, including `oldSelf` ratcheting and cost-budget exhaustion. Pass = server-identical error text.
- **SPIKE-VAP-OFFLINE**: build the VAP/MAP validator the way Gatekeeper's `k8scel` driver does (`validating.NewValidator` + `cel.NewCompositedCompiler`) with params, `namespaceObject` and an RBAC-backed `authorizer` from a snapshot; compare against `kubectl --dry-run=server` on a kind cluster with the same policies. Also answers whether `request.userInfo` is reachable (open question, brief: gap-k8s-offline-fidelity-facts §6).
- **SPIKE-KYVERNO-CLI**: `kyverno apply --context-file --parameter-resource --userinfo --policy-report` for ClusterPolicy, ValidatingPolicy, VAP with paramRef and MAP, with zhi-generated side files; confirm exit-code ownership and the `--crd-paths` rename.
- **SPIKE-VENDOR-FORK**: copy LimitRanger, RBAC `RulesAllow` and the pod/PVC quota evaluators from `kubernetes@v1.37.0`; confirm they compile against staging modules only, without `k8s.io/kubernetes`, and that `pkg/apis/core` type conversion is bounded (flagged UNVERIFIED in the embedding brief §5).
- **SPIKE-HELM-SCHEMA**: Helm 4.3 `lint`/`template` accepting a 2020-12 `values.schema.json` with the `x-zhi-*` vocabulary end-to-end, and the merged-`.Values`-versus-all-subchart-schemas semantics reproduced in-process.
- **SPIKE-LINEAGE**: on three real charts, measure what fraction of rendered-manifest findings can be mapped back to a values pointer by `x-zhi-targets` plus scalar fingerprinting; decide whether perturbation rendering is needed in phase 2.
- **SPIKE-SCC**: `sccmatching` offline with a synthesized authorizer from snapshot RBAC and a placeholder UID range for a namespace the PR creates; calibrate against `oc adm policy scc-subject-review` on a real OpenShift 4.18+ cluster.
- **SPIKE-EVIDENCE**: produce a DSSE + SLSA VSA v1 bundle, push it as an OCI referrer, and verify it with cosign v3 `--offline --trusted-root` on an air-gapped machine; confirm the protobuf-bundle offline behaviour on 3.1.x (UNVERIFIED in the regulated brief).
- **SPIKE-FIPS**: build the full dependency set with `GOFIPS140=v1.0.0` and `GODEBUG=fips140=on`; confirm no ed25519-only path in Sigstore verification or the go-plugin handshake breaks.
- **SPIKE-IMPORT-DEGRADE**: run the importer against EKS, AKS and OpenShift with minimal RBAC; verify per-layer graceful degradation and that MAP v1/v1beta1 fallback and PSACT visibility behave as documented.
- **SPIKE-T1-BOOT** (phase-2 gate, not MVP): envtest and kwokctl boot time with a restored snapshot and `--admission-control-config-file`; the "seconds" claim is unbenchmarked.
- **SPIKE-SURVEY**: a short internal survey of the company's consultants on failure-class frequency and which distributions they actually deploy into this year (report §10.2 Q7, Q17), to order profiles and checks.

Structural risks beyond the spikes: native-type validation stays approximate for years because KEP-5073 will not publish rules to OpenAPI (report §10.1), so the UI must never overclaim; manifest-based `.static.k8s.io` policies are invisible to the API by design and can only arrive via the declared overlay; opaque platform webhooks (GKE Warden, AKS mutators) mean profiles drift from reality and need the post-merge calibration loop; the k8s.io minor pin (v0.37.0) must be bumped quarterly and cel-go's module rename must be tracked through k8s.io rather than imported directly; Kyverno's CVE cadence argues for subprocess isolation but adds a binary to distribute and license-notice; JSON Forms is a JS dependency in an otherwise Go product; and the vendor-forked upstream code is a per-minor maintenance obligation. The product risk the post-mortems warn about is the opposite of over-building: Datree died in a SaaS registry, Monokle outside the push path, Kubevious and Kubeapps attached to clusters (brief: gap-closest-competitors-deep-dive, Task C). This design is stateless, Git-native and file-based precisely to avoid those three graves.

## 12. Differentiation

The report's whitespace list (§8) says no product imports the cluster's admission posture into a portable signed snapshot, runs every engine in one pre-push report with per-finding fidelity, lets one persona author what another fills, writes a PR onto the repo the controller already watches, treats Compose as first-class, and keeps validator extensibility open-source. The environment-matrix-and-evidence angle adds two more nobody offers: a computed compatibility matrix across many customer clusters, and auditor-grade evidence.

- **ConfigHub** validates on edit (`vet-schemas`, `vet-celexpr`, Triggers) but replaces Git as the source of truth, delivers OCI-pull only since August 2026, and imports no admission, quota or CRD state (report §8; deep-dive). zhi is Git-native and snapshot-aware; it could even publish to ConfigHub as a target, but it competes on "who owns the truth", and consultancies cannot put eleven customers' truth in a vendor database.
- **Devtron** is the strongest living OSS incumbent (schema GUI ↔ YAML, per-scope overrides, locked keys and approvals) but it is a whole in-cluster platform that owns its manifest repo, has no policy engine or snapshot, and gates the interesting bits as Enterprise (report §4.6; deep-dive). zhi copies the schema-per-scope idea and nothing else; it works against the customer's own repo and cluster without installing anything there, which is the only shape a consultant is allowed to bring.
- **Flux Schema** reuses the apiserver's CEL code for CRD validation and is Apache-2.0, so it is the CRD/CEL layer of a pseudo cluster and nothing more: no values model, no VAP/MAP/Kyverno/Gatekeeper/PSA/quota, no UI, no Git write, and its ecosystem catalog is AGPL (report §8; deep-dive). zhi generates its own catalog from the customer's CRDs (the import feature) and can shell out to flux-schema as one engine among several.
- **Replicated** is the reference for the contract split and zhi deliberately speaks its dialects (`values.schema.json`, Troubleshoot analyzers, a `Preflight` Secret). But KOTS preflights run at install time inside the customer cluster, need the proprietary control plane at $2–3k/month plus per-license fees, and add an in-cluster admin console that reviews call heavy (brief: persona-vendor-to-customer). zhi evaluates the same requirements offline against a snapshot before the PR, with no runtime footprint; for Replicated customers it is complementary and for everyone else it is the open alternative.
- **Cyclops** is the closest "form from `values.schema.json`" UI, yet it needs an in-cluster controller and CRD, commits directly rather than by PR, has no policy awareness and is slowing (report §4.6; deep-dive). zhi takes the schema-to-form idea and keeps everything stateless and cluster-detached.
- **Kargo** promotes and already opens PRs, but has no validation step and its custom container steps are Enterprise-only (report §4.1, §10.1). zhi is the validator in front of Kargo's PR and the CommitStatus behind gitops-promoter: a complement, positioned so that Kargo OSS users get the gate without buying Enterprise.

The positioning sentence the report arrives at is the one to keep: the pre-push validator the controllers lack, above Helm/Kustomize/Compose (never fighting them, as Glasskube did), beside Argo/Flux/Kargo (never becoming their UI, as Weave GitOps did), and stateless with respect to the cluster (never cluster-attached, as Kubevious, Kubeapps and Cyclops were) (report §8). For regulated procurement specifically, no competitor in the research ships a signed, offline-verifiable, deterministic validation attestation bound to the rendered-manifest and snapshot digests; that is the line item that gets a consultancy through a bank's vendor review.

## 13. "If I had half the time"

Cut in this order, keeping the wedge that no competitor has: snapshot import/export/sign/verify, Tier 0 validation, environments with a matrix, and a PR with evidence.

1. **No web UI in the first release.** Ship CLI + CI + PR comment; render the matrix as Markdown in the PR and as a terminal table. The form comes later; a consultant edits YAML with the generated `.zhi/schema.json` modeline for editor completion, which is nearly free (report §9 #28).
2. **No Compose.** Keep the domain model target-agnostic so it lands cleanly later, but ship Kubernetes only.
3. **No Gatekeeper/OPA embedding.** Consume the VAP/VAPB Gatekeeper generates since v3.20 and shell out to `gator test` for Rego templates; embed OPA later (report §10.2 Q5).
4. **Vanilla + OpenShift profiles only**, chosen by the survey spike; AKS/GKE/EKS/Rancher become data-plus-emulator work in phase 2.
5. **Evidence stays, audit log goes.** DSSE/VSA and deterministic reports are a few hundred lines on top of an already-canonical report and are the procurement wedge; the hash-chained audit log and predicted-vs-observed watch wait.
6. **FIPS build stays, SBOM stays** (release-pipeline configuration, not code); the private-Sigstore signing story waits.
7. **No LSP, no MCP, no `resolver/v1`.** First-party SOPS/ESO reference handling only; Vault via resolver later.
8. **No Kyverno mutations or MAP application in the mutated-object diff**; report Blocking/Warning without the "what the cluster will store" view.

What must not be cut even at half time: the snapshot format and importer with graceful degradation, the ordered emulation with per-finding fidelity tags, JSON Pointer addressing with source positions, comment-preserving write-back, and the two developer contract files in standard shapes. Those are the parts that are expensive to retrofit and the parts the research says nobody else has (report §8; audit brief lessons 1, 3, 4, 5).
